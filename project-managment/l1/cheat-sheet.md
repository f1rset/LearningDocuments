## 📌 TL;DR — Найголовніше за 60 секунд
* **Проект (Project):** Тимчасове починання (має Start & End Date) для створення унікального результату в межах обмежень (Scope, Time, Cost).
* **Програма:** Група пов'язаних проектів зі спільною бізнес-метою. **Портфоліо:** Сукупність проектів/програм/операцій для досягнення стратегічних цілей організації.
* **Золотий трикутник:** Обсяг (Scope), Час (Time), Бюджет (Cost). В центрі — Якість (Quality). Зміна одного параметра неодмінно впливає на решту.
* **PM (Project Manager):** Організовує середовище, координує завдання, керує ризиками, звітує стейкхолдерам. Не зобов'язаний виконувати всю технічну роботу особисто.
* **Життєвий цикл:** 
  * *Waterfall:* жорсткі фази, підходить для фіксованих стабільних вимог.
  * *V-Model:* дзеркальні рівні декомпозиції та тестування, простежуваність (*Traceability*), стандарт для безпеко-критичних систем.
  * *Agile/Scrum:* короткі ітерації, гнучкість, швидка реакція на зміни.
  * *Гібридний підхід:* Organization (Waterfall) $\to$ Product (V-Model) $\to$ Software (Agile).
* **Майлстоун (Milestone):** Контрольна точка звітності/аудиту. Рішення: *Pass*, *Conditional Pass*, *Fail*.

## 📊 Порівняльна матриця: Project vs Program vs Portfolio

| Критерій | Проект (Project) | Програма (Program) | Портфоліо (Portfolio) |
| :--- | :--- | :--- | :--- |
| **Масштаб (Scope)** | Чітко визначені межі результату | Комплексний, спільний бізнес-результат | Стратегічні цілі всієї компанії |
| **Зміни (Change)** | Зміни мінімізуються та суворо контролюються | Зміни адаптуються між проектами програми | Зміни визначаються ринком та стратегією |
| **Успіх (Success)** | Досягнення цілі в межах часу, бюджету, якості | Досягнення бізнес-вигоди (*Business Benefits*) | Окупність інвестицій (ROI) всього портфеля |
| **Керівник** | Project Manager (PM) | Program Manager (PgM) | Portfolio Manager / C-level (CTO, VP) |

## 🔄 Моделі життєвого циклу проекту: Матриця вибору

| Модель | Коли використовувати | Плюси | Мінуси |
| :--- | :--- | :--- | :--- |
| **Waterfall (Послідовна)** | Стабільні, відомі наперед вимоги; жорсткі контракти Fixed Price | Передбачуваність, чіткі терміни та кошторис | Дорогі зміни, пізнє виявлення помилок |
| **V-Model (V-подібна)** | Високі вимоги до надійності (Auto, MedTech, Aero) | Сувора верифікація на кожному рівні, Traceability | Високі бюрократичні витрати |
| **Agile (Scrum / Kanban)** | Стартапи, веб/мобільна розробка, динамічні вимоги | Швидкий Time-to-Market, гнучкість, постійний фідбек | Важко зафіксувати бюджет і кінцеві терміни |
| **Гібридна модель** | Складні HW+SW системи (автомотів, робототехніка) | Баланс стабільності «заліза» та гнучкості софту | Потребує високої зрілості процесів |

## 🛠️ Інженерні евристики та правила PM (Rules of Thumb)
1. **Правило трикутника обмежень:** *«Швидко, Якісно, Дешево — виберіть будь-які два»*.
2. **Правило майлстоунів:** Майлстоун — це нульова тривалість у графіку ($Duration = 0$), що фіксує факт передачі результату (*Deliverable*), а не сам процес роботи.
3. **Правило відповідальності PM:** Якщо задача не має призначеного виконавця — за неї персонально відповідає PM.
