## 📌 TL;DR — Квінтесенція курсу (Core Highlights)

* **Архітектура фон Неймана:** Спільна пам'ять для коду та даних. "Пляшкове горло" пом'якшується ієрархією кешів L1/L2/L3.
* **System V x86-64 ABI:** Аргументи у `%rdi, %rsi, %rdx, %rcx, %r8, %r9`, результат у `%rax`, вирівнювання стека по 16 байт.
* **Конвеєр (Pipeline):** 5 стадій (IF, ID, EX, MEM, WB). Конфлікти: Structural (I/D кеші), Data RAW (Forwarding + 1 такт Load-Use затримки), Control (2-bit Branch Prediction).
* **Кеш-пам'ять:** Адреса = `[ Tag | Set Index | Block Offset ]`. $\text{AMAT} = \text{Hit Time} + \text{Miss Rate} \times \text{Miss Penalty}$. Протокол MESI.
* **Дворежимність процесора:** Ring 3 (User) $\xrightarrow{\text{syscall}}$ Ring 0 (Kernel).
* **Процес vs Потік:** Процес = ізольований адресний простір (`fork`/`exec`/`CR3`), Потік = спільна пам'ять, власний стек і регістри (`clone`/`pthread`).
* **Планування CPU:** FCFS (ефект конвою), SJF (мінімум очікування), Round Robin (квант $q$), Linux CFS (`vruntime`, Red-Black tree).
* **Синхронізація:** Атомарний CAS, М'ютекс (сон), Спінлок (busy-wait), Семафор ($P/V$). 4 умови дедлоку Кофмана.
* **Віртуальна пам'ять:** Сторінки 4 КБ. 4-рівнева таблиця x86-64 (PML4 $\to$ PDP $\to$ PD $\to$ PT). Кеш трансляцій TLB. Алгоритм Clock.
* **Файлові системи:** VFS $\to$ Inode (метадані + блоки). Журналювання (WAL) та CoW (ZFS/Btrfs).
* **Контейнери:** Namespaces (ізоляція видимості) + Cgroups (ліміти CPU/RAM) + OverlayFS поверх спільного ядра Linux.
* **Безпека:** ASLR (рандомізація), Stack Canaries (захист стека), DEP/NX ($W \oplus X$).

## 1. Регістри x86-64 та угода про виклики (System V AMD64 ABI)

| 64-бітний регістр | 32-бітний підрегістр | Роль за стандартом System V AMD64 ABI | Збереження (Preservation) |
| :--- | :--- | :--- | :--- |
| `%rax` | `%eax` | Результат функції (Return Value) | **Caller-saved** (Scratch) |
| `%rdi` | `%edi` | **1-й аргумент функції** | **Caller-saved** |
| `%rsi` | `%esi` | **2-й аргумент функції** | **Caller-saved** |
| `%rdx` | `%edx` | **3-й аргумент функції** / 2-й результат | **Caller-saved** |
| `%rcx` | `%ecx` | **4-й аргумент функції** | **Caller-saved** |
| `%r8` | `%r8d` | **5-й аргумент функції** | **Caller-saved** |
| `%r9` | `%r9d` | **6-й аргумент функції** | **Caller-saved** |
| `%rsp` | `%esp` | **Stack Pointer** (Вершина стека) | **Callee-saved** |
| `%rbp` | `%ebp` | **Base / Frame Pointer** (База кадру) | **Callee-saved** |
| `%rbx` | `%ebx` | Регістр загального призначення | **Callee-saved** |
| `%r10` - `%r11` | `%r10d`.. | Тимчасові регістри (Syscall clobbers r11) | **Caller-saved** |
| `%r12` - `%r15` | `%r12d`.. | Регістри загального призначення | **Callee-saved** |

* **SIB-адресація:** $\text{Адреса} = \text{Imm} + \text{Base} + (\text{Index} \times \text{Scale}), \quad \text{Scale} \in \{1, 2, 4, 8\}$.
* **Системні виклики (Linux Syscall):** Номер виклику в `%rax`, аргументи в `%rdi, %rsi, %rdx, %r10, %r8, %r9`, інструкція `syscall`.

## 2. Конвеєр процесора та кеш-пам'ять (Pipeline & Caches)

### 2.1. Конфлікти 5-ступеневого конвеєра (Pipeline Hazards)
* **Structural:** Конфлікт за залізо $\implies$ роздільні L1 I-Cache та L1 D-Cache.
* **Data RAW (Read-After-Write):** $\implies$ Апаратне пересилання (Forwarding). Для `Load-Use` — обов'язкова затримка в **1 такт (Stall)**.
* **Control (Branches):** $\implies$ 2-бітні динамічні лічильники передбачення переходів (Branch Prediction) та BTB.

### 2.2. Формули та адресація кешу
* **Розбиття адреси:** $\text{Address} = [\; \text{Tag } (t) \;|\; \text{Set Index } (s) \;|\; \text{Block Offset } (b) \;]$.
* Кількість наборів: $S = 2^s$, Розмір блоку: $B = 2^b$ байтів (зазвичай 64 B), Асоціативність: $E$ рядків на набір.
* Ємність: $C = S \times E \times B$.
* **3C+1C Промахи:** **C**ompulsory (холодні), **C**apacity (малий кеш), **C**onflict (накладання в наборі), **C**oherence (інвалідація іншим ядром).
* **Протокол MESI:** **M**odified (брудний), **E**xclusive (чистий монопольний), **S**hared (спільний чистий), **I**nvalid (недійсний).

## 3. Процеси, потоки та планування CPU (Processes & Scheduling)

### 3.1. Адресний простір процесу в Linux
```text
  [Kernel Space] -> [User Stack v] -> [Shared Libs/mmap] -> [Heap ^] -> [BSS] -> [Data] -> [Text/Code]
```

### 3.2. Алгоритми планування процесора (CPU Scheduling)

| Алгоритм | Тип | Переваги | Недоліки |
| :--- | :--- | :--- | :--- |
| **FCFS** | Невитискальний | Простий ($O(1)$) | Ефект конвою (довге очікування) |
| **SJF / SRTF** | Невит. / Витиск. | **Мінімальний середній час очікування** | Потребує прогнозування сплесків; голодування |
| **Round Robin** | Витискальний | Справедливий, низький час відгуку | Чутливий до вибору кванта $q$ (Context Switch overhead) |
| **MLFQ** | Витискальний | Адаптивний (пріоритет I/O перед CPU) | Потребує тонкого налаштування черг |
| **Linux CFS** | Витискальний | Ідеально справедливий, зважений за `nice` | $O(\log N)$ вибір/вставка через Red-Black Tree (`vruntime`) |

## 4. Синхронізація та дедлоки (Synchronization & Deadlocks)

### 4.1. Примітиви блокування
* **CAS (`Compare-And-Swap`):** Атомарна основа Lock-Free алгоритмів.
* **М'ютекс vs Спінлок:** М'ютекс переводить потік у стан сну (блокування ядра); Спінлок виконує активне очікування (Busy-Waiting, для коротких секцій ядра).
* **Семафор:** $P(S)$ / `wait` (зменшує), $V(S)$ / `signal` (збільшує).

### 4.2. Дедлок (Deadlock): 4 умови Кофмана
1. **Mutual Exclusion** (неподільність ресурсів).
2. **Hold and Wait** (утримання одного ресурсу при очікуванні іншого).
3. **No Preemption** (неможливість примусового відбору).
4. **Circular Wait** (замкнене коло очікування).
* *Головний захист:* **Упорядкування захоплення м'ютексів (Global Lock Ordering)**.

## 5. Віртуальна пам'ять та заміщення сторінок (Virtual Memory)

* **4-Рівнева трансляція x86-64:** `CR3` $\to$ `PML4[9]` $\to$ `PDP[9]` $\to$ `PD[9]` $\to$ `PT[9]` + `Offset[12]` $\to$ Фізичний байт.
* **TLB:** Апаратний кеш трансляцій. Huge Pages (2 MB / 1 GB) різко зменшують кількість промахів TLB.
* **Page Fault:** Переривання #14 $\to$ читання сторінки з диска/Swap у вільний кадр $\to$ оновлення PTE (`Present=1`) $\to$ перезапуск команди.
* **Алгоритм Clock (Другий шанс):** Стрілка обходить циклічний буфер сторінок: якщо `Accessed = 1`, скидає в `0`; якщо `Accessed = 0`, вибирає сторінку для вивантаження.

## 6. Файлові системи, RAID та сховища (Storage & File Systems)

* **UNIX Inode:** Метадані (права, розмір, час) + 12 прямих покажчиків блоків + Одинарний + Подвійний + Потрійний непрямі покажчики.
* **Журналювання (WAL):** Ext4 / NTFS гарантують цілісність метаданих через попередній запис транзакцій у журнал перед записом на диск.
* **SSD NAND Flash:** Читання/запис сторінками (4 KB), стирання цілими блоками (4 MB). FTL забезпечує Wear Leveling та TRIM.

| RAID Рівень | Схема | Ємність | Стійкість | Головне застосування |
| :--- | :--- | :--- | :--- | :--- |
| **RAID 0** | Striping (Чередування) | $N \times S$ | **0 дисків** (Немає захисту) | Максимальна швидкість (тимчасові дані) |
| **RAID 1** | Mirroring (Дзеркало) | $1 \times S$ | 1 диск з пари | Висока надійність ОС |
| **RAID 5** | Striping + Distributed Parity | $(N - 1) \times S$ | 1 будь-який диск | Баланс ціни, швидкості та надійності |
| **RAID 6** | Striping + Dual Parity | $(N - 2) \times S$ | 2 будь-які диски | Великі дискові сховища |
| **RAID 10** | Mirroring + Striping (1+0) | $(N / 2) \times S$ | До 1 диска в кожному дзеркалі | Високонавантажені СУБД (PostgreSQL) |

## 7. Віртуалізація, контейнери та безпека (Containers & Security)

### 7.1. Тріада технологій Linux-контейнерів (Docker)
1. **Namespaces (Ізоляція видимості):** `pid` (процеси), `net` (мережа), `mnt` (файли), `ipc`, `uts`, `user`.
2. **Cgroups v2 (Обмеження ресурсів):** `cpu.max`, `memory.max`, `io.max`.
3. **OverlayFS (Шарувата ФС):** Нижній Read-Only шар образу + Верхній Read-Write шар контейнера (Copy-up).

### 7.2. Тріада захисту пам'яті бінарних програм
1. **DEP / NX ($W \oplus X$):** Пам'ять або доступна для запису, або виконувана, але не обидва одночасно.
2. **ASLR:** Рандомізація адрес стека, купи та бібліотек при кожному старті програми.
3. **Stack Canaries:** Випадкове контрольне число перед адресою повернення на стеку для блокування Buffer Overflow.
