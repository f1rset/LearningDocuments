# 06. Управління процесами та перемикання контексту (Process Management & Context Switching)

## 🎯 Ключові концепції (Core Concepts)
1. **Концепція процесу (Process Abstraction):** Одиниця володіння ресурсами та ізоляції в операційній системі.
2. **Анатомія адресного простору процесу:** Сегменти Text (код), Data, BSS, Heap (динамічна пам'ять), Memory Mapped (бібліотеки), Stack (локальні змінні), Kernel Space.
3. **Блок керування процесом (PCB / `task_struct`):** Структура даних ядра, що описує стан, регістри, дескриптори та пам'ять процесу.
4. **Життєвий цикл та модель 5 станів процесу:** New $\to$ Ready $\to$ Running $\to$ Waiting/Blocked $\to$ Terminated.
5. **API управління процесами в POSIX:** `fork()`, `execve()`, `waitpid()`, `exit()`, оптимізація Copy-on-Write (CoW).
6. **Процеси-зомбі (Zombies) та процеси-сироти (Orphans):** Роль процесу `init` (PID 1).
7. **Механізм перемикання контексту (Context Switch):** Збереження/відновлення стану CPU, перемикання `CR3` та непрямі витрати (TLB/Cache misses).

## 1. Анатомія адресного простору процесу (Process Memory Layout)

Кожен процес у сучасній ОС має ілюзію повного монопольного володіння всім 64-бітним віртуальним адресним простором (наприклад, 128 ТБ у Linux x86-64):

```text
  Старші адреси (0xFFFFFFFFFFFFFFFF)
  +-----------------------------------------------------------+
  | Kernel Space (Пам'ять ядра ОС: недоступна в User Mode)    |
  +-----------------------------------------------------------+
  | User Stack (Стек: росте вниз v )                          |
  +-----------------------------------------------------------+
  |                           |                               |
  |                           v                               |
  |                                                           |
  |                           ^                               |
  |                           |                               |
  +-----------------------------------------------------------+
  | Memory Mapping Segment (Спільні бібліотеки .so, mmap)     |
  +-----------------------------------------------------------+
  | Heap (Купа: динамічна пам'ять malloc/free, росте вгору ^) |
  +-----------------------------------------------------------+
  | BSS Segment (Неініціалізовані глобальні змінні = 0)       |
  +-----------------------------------------------------------+
  | Data Segment (Ініціалізовані глобальні та статичні змінні)|
  +-----------------------------------------------------------+
  | Text / Code Segment (Машинний код: Read-Only, Executable) |
  +-----------------------------------------------------------+
  Молодші адреси (0x0000000000400000)
```

* **Сегмент тексту (Text/Code):** Машинні інструкції програми. Захищений від запису; однаковий код розділяється кількома екземплярами процесу.
* **Сегмент Data:** Глобальні змінні з початковим значенням (напр., `int count = 10;`).
* **Сегмент BSS (Block Started by Symbol):** Глобальні змінні без явного значення (напр., `int arr[1000];`). У виконуваному ELF-файлі займає 0 байтів, а ядро просто заповнює його нулями при завантаженні.
* **Купа (Heap):** Росте вгору до старших адрес. Керується системними викликами `brk()` / `sbrk()` та `mmap()`.
* **Стек (Stack):** Росте вниз до молодших адрес. Зберігає параметри викликів, адреси повернення та локальні змінні функцій.

## 2. Блок керування процесом (Process Control Block - PCB)

Ядро ОС представляє кожен процес у пам'яті у вигляді структури PCB (у ядрі Linux — **`struct task_struct`**):

1. **Ідентифікатори:** `PID` (Process ID), `PPID` (Parent PID), `UID` (User ID), `GID` (Group ID).
2. **Стан процесу (Process State):** Ready, Running, Sleeping тощо.
3. **Контекст процесу (CPU Register Context):** Збережені значення регістрів (RAX, RBX, RSP, RIP, RFLAGS) на момент зупинки процесу.
4. **Управління пам'яттю (`mm_struct`):** Покажчик на кореневу таблицю сторінок (регістр `CR3`), межі сегментів пам'яті.
5. **Таблиця дескрипторів файлів (`files_struct`):** Масив покажчиків на відкриті файли/сокети (`0 = stdin`, `1 = stdout`, `2 = stderr`).
6. **Інформація планувальника:** Пріоритет (Nice value від -20 до +19), час виконання на CPU (`vruntime`).

## 3. Життєвий цикл та стани процесу (Process State Model)

```text
               +-------------------------------------------+
               |                  NEW                      |
               +-------------------------------------------+
                                     | Admitted (Створення)
                                     v
               +-------------------------------------------+
         +---> |                 READY                     | <---+
         |     | (Готовий до виконання, стоїть у черзі)   |     |
         |     +-------------------------------------------+     |
         |               |                           ^           |
   I/O   |      Schedule |                  Preempt  | Time      |
   Event |      Dispatch |                 (Таймер)  | Quantum   |
         |               v                           | Expired   |
         |     +-------------------------------------------+     |
         |     |                RUNNING                    | ----+
         |     | (Виконується на фізичному ядрі CPU)       |
         |     +-------------------------------------------+
         |               |
         |      Wait I/O | or System Event
         |               v
         |     +-------------------------------------------+
         +---- |             WAITING / BLOCKED             |
               | (Заблокований, очікує завершення I/O/події|
               +-------------------------------------------+
                                 | Exit
                                 v
               +-------------------------------------------+
               |               TERMINATED                  |
               | (Завершений, очікує виклику wait/Zombie)  |
               +-------------------------------------------+
```

## 4. Створення та завершення процесів у POSIX (`fork` & `exec`)

### 4.1. Системний виклик `fork()`
Створює новий процес-нащадок (Child), який є **точною копією** батьківського процесу (Parent):
* Батько і нащадок продовжують виконання з однієї й тієї самої точки після `fork()`.
* **Повертане значення `fork()`:**
  * У батьківському процесі повертає **PID створеного нащадка** ($> 0$).
  * У процесі-нащадку повертає **$0$**.
  * У разі помилки повертає $-1$.

```c
pid_t pid = fork();
if (pid < 0) {
    perror("Fork failed");
} else if (pid == 0) {
    // Код нащадка (Child Process)
    printf("I am child with PID: %d\n", getpid());
} else {
    // Код батька (Parent Process)
    printf("I am parent of child with PID: %d\n", pid);
    waitpid(pid, NULL, 0); // Очікування завершення нащадка
}
```

### 4.2. Оптимізація Copy-on-Write (CoW)
При виклику `fork()` ядро ОС **не копіює** гігабайти фізичної пам'яті батька в нащадка. Натомість:
1. Таблиця сторінок нащадка вказує на **ті самі фізичні кадри пам'яті**, що й у батька.
2. Усі сторінки позначаються в таблиці як **Read-Only**.
3. Якщо будь-який з процесів намагається зробити запис у сторінку, апаратний блок MMU генерує `Page Fault`.
4. Ядро ОС перехоплює виняток, виділяє новий фізичний кадр, **копіює лише цю одну змінену сторінку (4 КБ)**, оновлює права на запис і повторює інструкцію.

### 4.3. Системний виклик `execve()`
Повністю замінює поточний образ пам'яті процесу новим виконуваним файлом:
* Очищує старий стек, купу та сегмент коду, завантажує нову програму з диска і передає керування функції `main()`.
* PID процесу при цьому **не змінюється**!

### 4.4. Процеси-зомбі (Zombie) та сироти (Orphan)
* **Зомбі (Zombie / `<defunct>`):** Процес, який викликав `exit()`, звільнив свою пам'ять, але його запис у таблиці процесів ядра зберігається, доки батько не викличе `wait()`/`waitpid()` для зчитування коду повернення.
* **Сирота (Orphan):** Процес, чий батьківський процес завершився раніше за нього. Такі процеси автоматично всиновлюються кореневим процесом ОС **`init` / `systemd` (PID 1)**, який періодично викликає `wait()` і очищує завершених нащадків.

## 5. Перемикання контексту (Context Switching)

**Перемикання контексту** — це процес збереження стану поточного процесу (Context Save) та завантаження стану іншого процесу (Context Restore) для продовження його виконання на CPU.

```text
   Процес P0                     Ядро ОС (Kernel)                  Процес P1
   [Виконується]
         |
   Таймер / Syscall ----> Збереження стану P0 у PCB_0
                              Планувальник вибирає P1
                          Завантаження стану P1 з PCB_1 ----> [Виконується]
                                                                    |
                          Збереження стану P1 у PCB_1 <---- Syscall / Таймер
                              Планувальник вибирає P0
   [Виконується] <------- Завантаження стану P0 з PCB_0
```

* **Прямі витрати (Direct Overhead):** Збереження/відновлення 16 регістрів CPU, покажчика стека `RSP`, лічильника `RIP`, перемикання регістра кореня таблиць сторінок `CR3`.
* **Непрямі витрати (Indirect Overhead - значно дорожчі!):**
  1. **Скидання TLB (Translation Lookaside Buffer):** Зміна адресного простору робить недійсними кешовані адреси сторінок у TLB.
  2. **Забруднення кешів процесора (Cache Pollution):** Новий процес витісняє з L1/L2 кешів корисні дані попереднього процесу, викликаючи масові промахи кешу після перемикання.

---

## ⚠️ Підводні камені та типові помилки (Pitfalls)

1. **Витік процесів-зомбі (Zombie Leak):**
   Якщо демон створює нащадків через `fork()` і ніколи не викликає `waitpid()` або не встановлює обробник сигналу `SIGCHLD` (`signal(SIGCHLD, SIG_IGN)`), таблиця процесів ядра переповниться, і система не зможе створювати нові процеси (`fork: Resource temporarily unavailable`).
2. **Fork-бомби (Fork Bomb `:(){ :|:& };:`):**
   Нескінченна рекурсивна генерація процесів, яка за секунди вичерпує всі доступні PID та блокує ОС (захист: ліміти `ulimit -u` або cgroups `pids.max`).
3. **Нерозділення дескрипторів файлів при fork:**
   Після `fork()` батько і нащадок мають **спільну позицію курсору читання/запису (file offset)** у відкритих файлах, що може спричинити хаотичне перемішування даних при одночасному записі без блокувань.
