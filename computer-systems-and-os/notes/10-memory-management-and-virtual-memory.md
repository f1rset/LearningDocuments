# 10. Управління пам'яттю та віртуальна пам'ять (Memory Management & Virtual Memory)

## 🎯 Ключові концепції (Core Concepts)
1. **Фізичний vs Віртуальний адресний простір:** Ізоляція пам'яті та апаратний блок MMU (Memory Management Unit).
2. **Фрагментація пам'яті:** Внутрішня (Internal) та зовнішня (External) фрагментація.
3. **Сторінкова організація (Paging):** Віртуальні сторінки (Pages), фізичні кадри (Frames) та структура запису PTE (Present, R/W, User, Dirty, NX).
4. **Багаторівневі таблиці сторінок (Multi-Level Paging):** 4-рівнева ієрархія x86-64 (PML4 $\to$ PDP $\to$ PD $\to$ PT) та регістр `CR3`.
5. **Буфер трансляції адрес (TLB - Translation Lookaside Buffer):** Апаратний кеш сторінок, вартість Page Walk, Huge Pages (2 МБ / 1 ГБ) та PCID.
6. **Віртуальна пам'ять за вимогою (Demand Paging):** Обробка винятку Page Fault, файл підкачки (Swap).
7. **Алгоритми заміщення сторінок:** Оптимальний (OPT), FIFO (Аномалія Беладі), LRU та годинниковий алгоритм другого шансу (Clock Algorithm).
8. **Трашинг (Thrashing):** Катастрофічна деградація продуктивності та модель робочого набору (Working Set Model).

---

## 1. Концепція віртуальної пам'яті та трансляція адрес (MMU)

Віртуальна пам'ять забезпечує повну ізоляцію процесів один від одного та від ядра ОС:
* Програми працюють виключно з **віртуальними адресами (Virtual Addresses)**.
* Апаратний блок процесора **MMU (Memory Management Unit)** на льоту транслює кожну віртуальну адресу у відповідну **фізичну адресу (Physical Address)** в оперативній пам'яті (RAM).

```text
  Процес P1 (Virtual 0x4000) --\
                                +---> [ MMU + Page Tables ] ---> [ Фізична RAM: Кадр #12 ]
  Процес P2 (Virtual 0x4000) --/                                 [ Фізична RAM: Кадр #85 ]
```

---

## 2. Сторінкова організація пам'яті (Paging Architecture)

Адресний простір розбивається на блоки фіксованого розміру — **сторінки (Pages)** (стандартний розмір — **4 КБ = 4096 байтів**).
Фізична пам'ять розбивається на блоки такого самого розміру — **кадри (Page Frames)**.

* **Розбиття 32/48-бітної віртуальної адреси:**

```text
  +-------------------------------------+-----------------------+
  |  Virtual Page Number (VPN)          | Page Offset (12 бітів)|
  +-------------------------------------+-----------------------+
                                        11                     0
```
* **Page Offset (12 бітів):** Адресує конкретний байт всередині 4-кілобайтної сторінки ($2^{12} = 4096$). Зміщення **не змінюється** при трансляції!
* **VPN $\to$ PFN:** Номер віртуальної сторінки (VPN) замінюється через таблицю сторінок на номер фізичного кадру (Page Frame Number - PFN).

### 2.1. Структура запису таблиці сторінок (Page Table Entry - PTE)
Кожен 64-бітний запис PTE містить фізичну адресу кадру та біти атрибутів:

```text
  63 62                                       12 11 9 8 7 6 5 4 3 2 1 0
  +--+------------------------------------------+----+--+-+-+-+-+-+-+-+-+
  |NX| Physical Frame Address (PFN)             |Avail|G|PS|D|A|CD|WT|U|W|P|
  +--+------------------------------------------+----+--+-+-+-+-+-+-+-+-+
```
* `P` (Present / Valid): Сторінка завантажена у фізичну RAM ($1$) чи знаходиться на диску у Swap ($0$).
* `W` (Read/Write): Дозволено запис ($1$) чи тільки читання ($0$).
* `U` (User/Supervisor): Доступна з User Mode ($1$) чи тільки для ядра ($0$).
* `A` (Accessed): До сторінки зверталися (для алгоритмів LRU).
* `D` (Dirty): У сторінку виконувався запис (потрібно зберегти на диск при вивантаженні).
* `NX` (No-Execute / XD bit): Заборона виконання коду зі сторінки (захист від стек-оверфлоу атак).

## 3. Багаторівневі таблиці сторінок (Multi-Level Paging в x86-64)

В x86-64 використовується 48-бітний віртуальний простір. Однорівнева таблиця вимагала б $2^{36} \times 8 \text{ байт} = 512 \text{ ГБ}$ пам'яті лише під саму таблицю для кожного процесу!
Тому використовується **4-рівнева ієрархія таблиць сторінок**:

```text
  Віртуальна адреса (48 бітів):
  +---------+---------+---------+---------+---------------+
  | PML4 (9)| PDP (9) | PD (9)  | PT (9)  | Offset (12)   |
  +---------+---------+---------+---------+---------------+
  47      39 38     30 29     21 20     12 11            0
      |         |         |         |             |
      v         v         v         v             v
  CR3 -> [PML4] -> [PDP] -> [PD] -> [PT] -> [Фізичний Кадр] + Offset
```

* **Перевага:** Таблиці нижніх рівнів створюються в пам'яті **лише для тих діапазонів адрес, які реально використовуються процесом**. Якщо адреси не виділені, верхній покажчик просто дорівнює `NULL`.

---

## 4. Буфер трансляції адрес (TLB - Translation Lookaside Buffer)

Оскільки 4-рівневий обхід дерева сторінок (Page Table Walk) вимагає **4 послідовних звернень до RAM** на кожне читання пам'яті, процесор містить спеціальний високошвидкісний апаратний кеш — **TLB**:
* **TLB Hit:** Трансляція `VPN -> PFN` знайдена в TLB ($\approx 0.5\text{--}1$ такт).
* **TLB Miss:** Апаратний Page Table Walker виконує 4 звернення до RAM, знаходить адресу і записує її в TLB.
* **Huge Pages (Великі сторінки):** Використання сторінок по **2 МБ** (оминає рівень PT) або **1 ГБ** (оминає рівні PD та PT). Один запис у TLB тепер покриває в $512\times$ більше пам'яті, що критично прискорює СУБД (PostgreSQL, Redis, JVM).

---

## 5. Віртуальна пам'ять за вимогою та Page Fault (Demand Paging)

Сторінки завантажуються в оперативну пам'ять лише в момент першого звернення до них:

```text
  Інструкція звертається до віртуальної адреси
                      |
           Перевірка біта Present у PTE
           /                         \
    (P = 1: У пам'яті)        (P = 0: PAGE FAULT!)
           |                           |
     Доступ до RAM             1. CPU генерує переривання #14
                               2. Ядро ОС знаходить сторінку в Swap/Файлі
                               3. Ядро виділяє вільний фізичний кадр
                               4. Читання сторінки з диска (DMA)
                               5. Оновлення PTE (P=1, PFN)
                               6. CPU ПОВТОРЮЄ команду, що впала!
```

## 6. Алгоритми заміщення сторінок (Page Replacement Algorithms)

Коли фізична RAM заповнена, ядро повинно вибрати сторінку-жертву для вивантаження у Swap:

1. **Оптимальний алгоритм (OPT / Belady's MIN):**
   Вивантажує сторінку, до якої не буде звернень найдовше в майбутньому. Неможливий для реалізації на практиці (вимагає знання майбутнього), служить еталоном порівняння.
2. **FIFO (First-In, First-Out):**
   Вивантажує найстарішу сторінку.
   * **⚠️ Аномалія Беладі (Belady's Anomaly):** Для FIFO збільшення кількості фізичних кадрів пам'яті може призвести до **збільшення кількості Page Faults**!
3. **LRU (Least Recently Used):**
   Вивантажує сторінку, до якої не зверталися найдовше в минулому. Не страждає на аномалію Беладі, але точний облік часу дорогий апаратно.
4. **Годинниковий алгоритм другого шансу (Clock / Second-Chance Algorithm):**
   Ефективна апроксимація LRU через циклічний буфер і біт `Accessed` (Reference Bit):
   * Якщо стрілка вказує на сторінку з `A = 1` $\implies$ скидає `A = 0` (дає другий шанс) і рухається далі.
   * Якщо вказує на сторінку з `A = 0` $\implies$ вибирає її жертвою для вивантаження!

```text
                 Годинниковий алгоритм (Clock Algorithm):
                             [ Page 0 (A=0) ] <--- Стрілка вибирає цю!
                            /                \
               [ Page 3 (A=1) ]            [ Page 1 (A=1) ]
                            \                /
                             [ Page 2 (A=0) ]
```

## 7. Трашинг (Thrashing) та модель робочого набору

* **Трашинг (Thrashing):** Стан системи, коли сумарний розмір активної пам'яті всіх процесів перевищує фізичний обсяг RAM. Система витрачає майже $100\%$ часу на читання/запис сторінок зі Swap на диск (Page Faults), а завантаження CPU падає майже до нуля.
* **Модель робочого набору (Working Set Model):** Множина сторінок $W(t, \Delta)$, до яких процес звертався за останні $\Delta$ одиниць часу. Ядро дозволяє процесу виконуватися лише тоді, коли весь його Working Set повністю вміщується в фізичній RAM.

---

## ⚠️ Підводні камені та типові помилки (Pitfalls)

1. **Помилка сегментації (Segmentation Fault / SIGSEGV):**
   Виникає, коли програма звертається до неіснуючої сторінки або намагається записати в сторінку з правами Read-Only (наприклад, `char *str = "hello"; str[0] = 'H';`).
2. **Memory Overcommit та вбивця OOM (Out-Of-Memory Killer):**
   Linux виділяє віртуальну пам'ять оптимістично (Overcommit), вважаючи, що процеси не заповнять усю пам'ять одразу. Якщо RAM вичерпується повністю, спрацьовує OOM Killer і примусово вбиває найжадібніший процес (`kill -9`).
3. **Витік пам'яті (Memory Leak) в купі:**
   Невикликаний `free()` не призводить до збою одразу, але поступово роздуває Working Set процесу, що призводить до витіснення інших сторінок у Swap і падіння швидкості всієї системи.
