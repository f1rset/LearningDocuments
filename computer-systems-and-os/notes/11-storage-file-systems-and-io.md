# 11. Дискові підсистеми, файлові системи та I/O (Storage, File Systems & I/O)

## 🎯 Ключові концепції (Core Concepts)
1. **Фізичні носії даних:** Магнітні диски HDD (Seek time, Rotational delay) проти SSD на базі NAND Flash (сторінки vs блоки, FTL, Wear Leveling, TRIM).
2. **Дискові масиви RAID:** RAID 0 (Striping), RAID 1 (Mirroring), RAID 5 (Distributed Parity), RAID 6 та RAID 10.
3. **Віртуальна файлова система (VFS):** Рівень абстракції ядра (Superblock, Inode, Dentry, File).
4. **Структура файлових систем UNIX (Inode-based):** Прямі та непрямі покажчики блоків, жорсткі (Hard Links) та символічні (Symlinks) посилання.
5. **Надійність та журналювання (Journaling):** Запобігання пошкодженню метаданих (WAL), CoW файлові системи (ZFS, Btrfs).
6. **Архітектура вводу-виводу (I/O Architecture):** Опитування (Polling), переривання, Direct Memory Access (DMA), Memory-Mapped I/O та системний Page Cache.

## 1. Фізичні носії даних (Storage Hardware)

### 1.1. Магнітні жорсткі диски (HDD)
Механічний накопичувач: магнітні пластини обертаються (5400–7200 RPM), зчитувальна голівка позиціонується на доріжці:

$$\text{Total Access Time} = \text{Seek Time} + \text{Rotational Latency} + \text{Transfer Time}$$
* **Seek Time (Час пошуку):** Механічне переміщення голівки на потрібний циліндр ($\approx 3\text{--}10 \text{ ms}$ — найповільніша частина!).
* **Rotational Latency (Затримка обертання):** Очікування, доки потрібний сектор прокрутиться під голівку ($\approx 4.16 \text{ ms}$ для 7200 RPM).
* **Висновок:** HDD мають високу швидкість для **послідовного читання (Sequential I/O)**, але катастрофічно повільні для **випадкового доступу (Random I/O)**.

### 1.2. Твердотільні накопичувачі (SSD / NVMe Flash)
Електронна пам'ять без рухомих деталей. Має асиметричну структуру:
* **Сторінка (Page, 4–16 КБ):** Мінімальна одиниця **читання та запису**.
* **Блок (Block, 128–512 сторінок, 2–8 МБ):** Мінімальна одиниця **стирання**.
* **Особливість NAND Flash:** Неможливо перезаписати байт або сторінку напряму! Щоб записати нові дані у зайняту сторінку, потрібно спершу **стерти весь блок цілком**.

```text
       Структура Flash-пам'яті SSD:
       +-------------------------------------------------------------+
       |                      БЛОК (Block 4 MB)                      |
       |  +-------------+  +-------------+  ...  +-------------+     |
       |  | Page (4 KB) |  | Page (4 KB) |       | Page (4 KB) |     |
       |  +-------------+  +-------------+       +-------------+     |
       +-------------------------------------------------------------+
              ^ Запис/Читання                           ^ Стирання
```

* **FTL (Flash Translation Layer):** Вбудований мікроконтролер SSD, який реалізує:
  1. **Out-of-place запис:** Нові дані записуються у вільні сторінки, а старі позначаються застарілими (Stale).
  2. **Збирання сміття (Garbage Collection):** Копіювання дійсних сторінок у новий блок і очищення старого блоку (викликає коефіцієнт підсилення запису — **Write Amplification**).
  3. **Wear Leveling (Вирівнювання зносу):** Рівномірний розподіл записів по всіх комірках пам'яті.
  4. **Команда TRIM:** Дозволяє ОС повідомляти SSD, що видалені файли більше не потрібні, для завчасного очищення блоків.

## 2. Дискові масиви RAID (Redundant Array of Independent Disks)

```text
  RAID 0 (Striping)           RAID 1 (Mirroring)          RAID 5 (Parity)
  Disk 0    Disk 1            Disk 0    Disk 1            Disk 0   Disk 1   Disk 2
  +----+    +----+            +----+    +----+            +----+   +----+   +----+
  | A1 |    | A2 |            | A1 |    | A1 |            | A1 |   | A2 |   | Ap |
  | A3 |    | A4 |            | A2 |    | A2 |            | B1 |   | Bp |   | B2 |
  | A5 |    | A6 |            | A3 |    | A3 |            | Cp |   | C1 |   | C2 |
  +----+    +----+            +----+    +----+            +----+   +----+   +----+
  Швидкість x2, 0% захисту    50% ємності, 1 збій         (N-1) ємність, 1 збій
```

| Рівень RAID | Механізм | Мінімальна к-сть дисків | Корисна ємність | Стійкість до збоїв |
| :--- | :--- | :---: | :---: | :---: |
| **RAID 0** | Чередування (Striping) | 2 | $N \times S$ | Жодної (вихід 1 диска вбиває весь масив) |
| **RAID 1** | Дзеркалювання (Mirroring)| 2 | $1 \times S$ | Витримує відмову 1 диска з пари |
| **RAID 5** | Чередування з парністю ($XOR$) | 3 | $(N - 1) \times S$ | Витримує відмову **будь-якого 1 диска** |
| **RAID 6** | Подвійна парність | 4 | $(N - 2) \times S$ | Витримує одночасну відмову **будь-яких 2 дисків** |
| **RAID 10**| Дзеркалювання + Чередування (1+0) | 4 | $(N / 2) \times S$ | Висока швидкість та надійність |

## 3. Віртуальна файлова система та структура Inode (VFS)

В операційних системах сімейства UNIX «усе є файлом» завдяки рівню абстракції **VFS (Virtual File System)**.

```text
               Прикладні програми (open, read, write)
                                |
                                v
               [ VFS: Віртуальна файлова система ]
                 /              |              \
           [ Ext4 ]          [ XFS ]          [ NFS / ZFS ]
                 \              |              /
                  v             v             v
                    Блокові пристрої диска
```

### 3.1. Чотири ключові об'єкти VFS
1. **Суперблок (Superblock):** Описує стан файлової системи загалом (розмір блоку, кількість вільних inode, мітка монтування).
2. **Індексний дескриптор (Inode - Index Node):** Описує конкретний файл: розмір, права доступу (`chmod`), власник (`UID/GID`), час модифікації та **масив покажчиків на фізичні блоки даних на диску**.
   *(Ім'я файлу в самому inode НЕ зберігається!)*.
3. **Елемент каталогу (Dentry - Directory Entry):** Зв'язує текстове ім'я файлу з його номером `inode`.
4. **Файловий об'єкт (File Object):** Представляє відкритий файл у пам'яті конкретним процесом (зберігає поточний offset читання/запису).

```text
               Структура класичного Inode:
               +-----------------------------------------+
               | Права доступу: -rwxr-xr-x               |
               | Власник: UID 1000, GID 1000             |
               | Розмір: 1048576 байт                    |
               +-----------------------------------------+
               | Прямі блоки 0..11  ----> [Block #402]   |
               |                         [Block #403]   |
               | Одинарний непрямий ----> [Блок покажчиків] -> [Block #800]...
               | Подвійний непрямий ----> [Покажчики] -> [Покажчики] -> [Data]
               | Потрійний непрямий ----> ...            |
               +-----------------------------------------+
```

### 3.2. Жорсткі посилання vs Символічні посилання (Hard vs. Soft Links)
* **Жорстке посилання (Hard Link `ln file link`):** Новий запис у каталозі (dentry), який вказує на **той самий номер `inode`**.
  * Файл фізично видаляється з диска лише тоді, коли лічильник жорстких посилань в inode (`st_nlink`) падає до $0$.
  * Не можуть вказувати на каталоги та між різними файловими системами.
* **Символічне посилання (Symlink `ln -s target link`):** Окремий невеликий файл з власним `inode`, вмістом якого є текстовий шлях до цільового файлу. Може вказувати на будь-що і стає "битим" (Dangling), якщо ціль видалено.

## 4. Журналювання та надійність файлових систем (Journaling)

Раптове зникнення живлення під час запису файлу може порушити цілісність метаданих файлової системи:

* **Журналювання (Write-Ahead Logging - WAL у Ext4/NTFS):**
  1. Перед внесенням змін у саму файлову систему операція записується в окрему послідовну кільцеву область — **журнал (Journal)**.
  2. Записується маркер завершення транзакції (Commit).
  3. Зміни переносяться в основні структури файлової системи (Checkpointing).
  4. При раптовому збої система не сканує весь диск годинами через `fsck`, а за лічені секунди просто **перечитує журнал** і накочує незавершені транзакції.
* **Файлові системи Copy-on-Write (ZFS, Btrfs):**
  Ніколи не перезаписують існуючі блоки даних. Нові дані завжди пишуться у вільне місце, після чого покажчик оновлюється на новий блок (атомарна зміна). Забезпечує безкоштовні моментальні знімки файлової системи (**Snapshots**).

## 5. Архітектура вводу-виводу (I/O Architecture & DMA)

```text
   CPU (Ring 0)  ---- (1. Налаштовує передачу: адреса RAM, розмір) ----> [ DMA Контролер ]
        |                                                                      |
   Продовжує                                                           (2. Пряма передача
   виконувати корисну                                                       даних повз CPU)
   роботу...                                                                  v
        ^ <---- (3. Переривання від DMA: "Дані в RAM готові!") ------ [ SSD / Мережева карта ]
```

* **Direct Memory Access (DMA):** Спеціальний апаратний контролер передає байти безпосередньо між пристроєм I/O та оперативною пам'яттю **без участі центрального процесора**. CPU витрачає ресурси лише на ініціалізацію та фінальну обробку переривання.
* **Системний кеш сторінок (Page Cache):**
  Ядро ОС автоматично використовує всю вільну оперативну пам'ять для кешування дискових блоків. Повторне читання того самого файлу виконується зі швидкістю RAM. Записи буферизуються як "брудні сторінки" (Dirty Pages) і скидаються на диск демоном `flusher` у фоновому режимі або примусово викликом `fsync()`.

## ⚠️ Підводні камені та типові помилки (Pitfalls)

1. **Ілюзія збереження даних після виклику `close()`:**
   Виклики `write()` та `close()` повертають успіх відразу після запису даних у **системний Page Cache ядра**. Якщо через секунду вимкнеться живлення, дані будуть втрачені! Для гарантії запису на фізичний носій обов'язково викликати **`fsync(fd)`**.
2. **Переповнення Inodes при наявності вільного місця:**
   Файлова система може мати сотні гігабайтів вільного місця на диску, але видавати помилку `No space left on device`, якщо вичерпано ліміт створення дрібних файлів (закінчилися вільні індекси Inodes).
3. **Видалення відкритого великого файлу (Unlink Open File):**
   Якщо процес видалив лог-файл командою `rm`, але інший процес тримає його відкритим, місце на диску **не звільниться**, доки останній процес не закриє свій файловий дескриптор.
