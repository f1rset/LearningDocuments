# 05. Структура операційної системи та системні виклики (OS Structure & System Calls)

## 🎯 Ключові концепції (Core Concepts)
1. **Функції операційної системи:** Менеджер ресурсів (Resource Allocator) та розширена віртуальна машина (Extended Machine).
2. **Дворежимна робота процесора (Dual-Mode Operation):** Режим користувача (User Mode / Ring 3) та Режим ядра (Kernel Mode / Ring 0).
3. **Привілейовані інструкції (Privileged Instructions):** Прямий доступ до I/O, керування таймером та регістрами захисту (`CR3`).
4. **Переривання та винятки (Interrupts & Traps / Exceptions):** Таблиця векторів переривань (IDT / IVT) та апаратний стек переривань.
5. **Системні виклики (System Calls):** Інструкція `syscall`, передача параметрів через регістри та перемикання контексту ядра.
6. **Архітектури ядер ОС:** Монолітні ядра (Linux, BSD), мікроядра (seL4, Mach, QNX), гібридні ядра (Windows NT, macOS XNU) та завантажувані модулі ядра (LKM).

## 1. Апаратна підтримка операційної системи (Hardware Support for OS)

Щоб запобігти збоям системи через помилки або шкідливі дії користувацьких програм, сучасні процесори надають три обов'язкові апаратні механізми захисту:

### 1.1. Дворежимна робота (Dual-Mode Operation / Protection Rings)
Процесор має апаратний біт режиму (Mode Bit) у регістрі стану:
* **Режим користувача (User Mode / Ring 3):** Виконується прикладний код. Будь-яка спроба виконати привілейовану інструкцію викликає апаратний виняток (General Protection Fault / Crash).
* **Режим ядра (Kernel / Supervisor Mode / Ring 0):** Виконується ядро ОС. Дозволено повний безконтрольний доступ до всієї фізичної пам'яті та заліза.

```text
               +-------------------------------------------+
               | User Space: Додатки, Бібліотеки (Ring 3)  |
               +-------------------------------------------+
                                     |
                       Системний виклик (syscall) / Trap
                                     v
               +-------------------------------------------+
               | Kernel Space: Драйвери, Планувальник,    |
               |               Менеджер пам'яті (Ring 0)   |
               +-------------------------------------------+
```

### 1.2. Привілейовані інструкції (Privileged Instructions)
Інструкції, які можуть виконуватися **виключно в Ring 0**:
* Пряме читання/запис у порти вводу-виводу (`in`, `out`).
* Маніпуляція системними регістрами керування (`CR0`, `CR3` для перемикання таблиць сторінок, `MSR`).
* Зупинка процесора (`hlt`), заборона переривань (`cli`, `sti`).
* Налаштування апаратного таймера.

### 1.3. Апаратний таймер (Hardware Timer)
Про процесор періодично (наприклад, кожні 1–10 мс) генерує апаратне переривання від таймера (Timer Interrupt). Це гарантує, що **ядро ОС регулярно повертає собі контроль над CPU**, унеможливлюючи нескінченне зависання користувацького процесу в зацикленні (`while(1)`).

## 2. Переривання, пастки та винятки (Interrupts & Exceptions)

Будь-який перехід з User Mode в Kernel Mode відбувається через одну з трьох подій:

```text
                           ТИПИ ПЕРЕРИВАНЬ
                                  |
            +---------------------+---------------------+
            |                                           |
      Асинхронні (Hardware)                      Синхронні (Software)
            |                                           |
    [ Апаратні переривання ]                   +--------+--------+
    - Сигнал таймера                           |                 |
    - Натискання клавіші                 [ Винятки / Faults ]  [ Пастки / Traps ]
    - Мережевий пакет                    - Ділення на нуль     - Системний виклик
    - Завершення DMA диска               - Page Fault            (syscall)
                                         - Порушення прав      - Точка зупину (int 3)
```

### 2.1. Таблиця дескрипторів переривань (Interrupt Descriptor Table - IDT)
Таблиця в пам'яті ядра (на яку вказує регістр процесора `IDTR`), де для кожного номера переривання ($0\dots 255$) записано адресу його обробника (**Interrupt Service Routine - ISR**):
* `0`: Divide by Zero
* `14`: Page Fault (відсутність сторінки в RAM)
* `128` (`0x80`): Системні виклики в застарілих 32-бітних Linux-системах.

* **Апаратна послідовність при виникненні переривання:**
  1. CPU зберігає в стек ядра регістри стану поточного процесу: `SS`, `RSP`, `RFLAGS`, `CS`, `RIP`.
  2. Встановлюється біт режиму ядра (Kernel Mode / Ring 0).
  3. Процесор завантажує адресу ISR з таблиці IDT у регістр `RIP`.
  4. Ядро обробляє подію та виконує команду повернення `iretq` (повертає збережені `RIP`, `RFLAGS`, перемикає CPU назад у User Mode).

## 3. Системні виклики (System Calls)

**Системний виклик (Syscall)** — це програмний запит від додатку до ядра ОС на виконання операцій з ресурсами (робота з файлами, створення процесів, мережа).

```text
  Користувацька програма        Бібліотека libc             Ядро ОС (Kernel)
   printf("Hello")  ----->  write(fd, buf, count)  ----->  sys_write()
                                    |                           |
                            mov $1, %rax (sys_write)            v
                            syscall  ===============>  Виконання драйвером
                            <========================  Повернення в libc
```

### 3.1. Механізм виконання системного виклику в Linux x86-64
1. Номер системного виклику записується в регістр `%rax` (наприклад, `sys_read = 0`, `sys_write = 1`, `sys_open = 2`, `sys_fork = 57`, `sys_execve = 59`).
2. Перші 6 аргументів системного виклику передаються через регістри:
   `%rdi` (1-й), `%rsi` (2-й), `%rdx` (3-й), `%r10` (4-й), `%r8` (5-й), `%r9` (6-й).
   *(Зверніть увагу: 4-й аргумент `%r10`, а не `%rcx`, оскільки інструкція `syscall` перезаписує `%rcx` адресою повернення)*.
3. Виконується апаратна інструкція **`syscall`**.
4. Процесор зберігає `RIP` в `%rcx`, `RFLAGS` в `%r11`, перемикається в Ring 0 і переходить за фіксованою адресою обробника `system_call_entry`.
5. Результат виконання повертається в регістрі `%rax` (від'ємне число від `-1` до `-4095` позначає код помилки `-errno`).

## 4. Архітектурні моделі ядер ОС (Kernel Architectures)

```text
   МОНОЛІТНЕ ЯДРО (Linux)              МІКРОЯДРО (Microkernel - seL4, QNX)
   +-------------------------------+   +------------------------------------+
   | User Space: Додатки           |   | User Space: Додатки, Файлова сист.,|
   +-------------------------------+   |             Драйвери, Мережа       |
   | KERNEL SPACE (Ring 0):        |   +------------------------------------+
   |  - Планувальник (Scheduler)   |   | KERNEL SPACE (Ring 0):             |
   |  - Менеджер пам'яті (MMU)     |   |  - Міжпроцесна взаємодія (IPC)     |
   |  - Файлові системи (Ext4)     |   |  - Базове планування (Threads)     |
   |  - Мережевий стек (TCP/IP)    |   |  - Низькорівнева пам'ять           |
   |  - Драйвери всіх пристроїв    |   +------------------------------------+
   +-------------------------------+
```

| Архітектура | Переваги | Недоліки | Приклади |
| :--- | :--- | :--- | :--- |
| **Монолітне (Monolithic)** | Максимальна продуктивність (усі виклики всередині ядра — це прямі виклики C-функцій у спільній пам'яті). | Будь-який баг або вразливість у драйвері призводить до повного падіння всієї системи (Kernel Panic). | Linux, FreeBSD, OpenBSD |
| **Мікроядро (Microkernel)** | Висока надійність та безпека: драйвери та ФС працюють як ізольовані користувацькі процеси; збій драйвера не вбиває систему. | Оверхед на постійні перемикання контексту та передачу повідомлень (IPC). | seL4, Minix 3, QNX Neutrino |
| **Гібридне (Hybrid)** | Модульність мікроядра поєднана зі швидкістю монолітного (критичні драйвери та графічний стек працюють у просторі ядра). | Складність структури ядра. | Windows NT, macOS (XNU) |

---

## ⚠️ Підводні камені та типові помилки (Pitfalls)

1. **Вартість переходу User/Kernel Mode (Syscall Overhead):**
   Системний виклик коштує в десятки разів дорожче за звичайний виклик функції через збереження регістрів, очищення кешу конвеєра, зміну таблиці сторінок (KPTI для захисту від Meltdown).
   * *Оптимізація:* Буферизований ввід/вивід (`fread`, `fwrite` з великими буферами замість побайтового `write()`), технологія `vDSO` (відображення системних викликів типу `gettimeofday` у User Space без перемикання в Ring 0) та `io_uring`.
2. **Плутанина між системними викликами та функціями C Standard Library:**
   Функція `printf()` не є системним викликом — це бібліотечна функція, яка накопичує байти в буфері і викликає системний виклик `write()` лише при заповненні буфера або символі `\n`.
3. **Пряме розіменування користувацьких покажчиків у ядрі:**
   Ядро ніколи не повинно читати дані з пам'яті користувача напряму через ризик збою Page Fault або атак; використовуються спеціальні захищені функції `copy_from_user()` / `copy_to_user()`.
