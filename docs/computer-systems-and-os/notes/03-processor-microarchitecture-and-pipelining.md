# 03. Мікроархітектура процесора та конвеєризація (Processor Microarchitecture & Pipelining)

## 🎯 Ключові концепції (Core Concepts)
1. **Тракт даних та пристрій керування (Datapath & Control):** Однотактові (Single-cycle) та багатотактові (Multi-cycle) процесори.
2. **Класичний 5-ступеневий конвеєр (5-Stage RISC Pipeline):** Ступені IF, ID, EX, MEM, WB та міжступеневі регістри.
3. **Метрики продуктивності:** CPI (Cycles Per Instruction), IPC (Instructions Per Cycle), час виконання програми.
4. **Конфлікти конвеєра (Pipeline Hazards):**
   * **Структурні конфлікти (Structural Hazards):** Нестача апаратних блоків.
   * **Конфлікти за даними (Data Hazards / RAW):** Залежності за даними, пересилання даних (Forwarding / Bypassing) та Load-Use затримка.
   * **Конфлікти керування (Control Hazards):** Умовні переходи, статичне та динамічне передбачення переходів (2-bit Branch Prediction).
5. **Сучасні високопродуктивні мікроархітектури:** Суперскалярність, позачергове виконання (Out-of-Order Execution - OoO), перейменування регістрів (Register Renaming) та Reorder Buffer (ROB).

---

## 1. Базові принципи організації процесора

### 1.1. Формула продуктивності процесора (Iron Law of Processor Performance)
$$\text{CPU Time} = \text{Instructions} \times \text{CPI} \times \text{Clock Cycle Time} = \frac{\text{Instructions} \times \text{CPI}}{\text{Clock Frequency}}$$

* **Однотактовий процесор (Single-Cycle):** Кожна інструкція виконується за рівно 1 такт тактової частоти ($\text{CPI} = 1$). Проте період такту $T_{\text{clk}}$ визначається найдовшою інструкцією (`load`), через що більшість блоків простоює, а частота дуже низька.
* **Конвеєрний процесор (Pipelined):** Інструкція розбивається на $k$ незалежних коротких стадій. Такт стає коротким ($T_{\text{clk}} / k$), і в ідеальному стані кожен такт завершується нова інструкція ($\text{CPI} \to 1$ при високій частоті!).

## 2. Класичний 5-ступеневий конвеєр інструкцій (5-Stage Pipeline)

```text
  Такт ->   1      2      3      4      5      6      7
  Instr 1: [IF] -> [ID] -> [EX] -> [MEM]-> [WB]
  Instr 2:        [IF] -> [ID] -> [EX] -> [MEM]-> [WB]
  Instr 3:               [IF] -> [ID] -> [EX] -> [MEM]-> [WB]
  Instr 4:                      [IF] -> [ID] -> [EX] -> [MEM]-> [WB]
  Instr 5:                             [IF] -> [ID] -> [EX] -> [MEM]-> [WB]
```

1. **IF (Instruction Fetch):** Зчитування інструкції з I-Cache за адресою `PC`, оновлення `PC = PC + 4`.
2. **ID (Instruction Decode & Reg Read):** Декодування коду операції, зчитування регістрів $R[rs1]$ та $R[rs2]$, розширення константи (Sign-extend).
3. **EX (Execute / Address Calculation):** Обчислення операції в ALU, обчислення цільової адреси переходу або адреси пам'яті.
4. **MEM (Memory Access):** Зчитування слова з D-Cache (`load`) або запис (`store`).
5. **WB (Write-Back):** Запис результату з ALU або пам'яті в регістровий файл $R[rd]$.

## 3. Конфлікти конвеєра (Pipeline Hazards) та методи їх усунення

Конфлікт (Hazard) — ситуація, за якої наступна інструкція не може виконатися в призначений їй такт, що викликає **зупинку конвеєра (Pipeline Stall / Bubble)**.

### 3.1. Структурні конфлікти (Structural Hazards)
Виникають, коли дві різні інструкції одночасно потребують одного й того самого апаратного ресурсу.
* *Класичний випадок:* Спроба одночасного читання інструкції на стадії IF та читання даних на стадії MEM через єдину пам'ять.
* *Вирішення:* Розділення кешів 1-го рівня на **L1 Instruction Cache** та **L1 Data Cache** (Гарвардський підхід).

### 3.2. Конфлікти за даними (Data Hazards)
Виникають, коли інструкція залежить від результату попередньої команди, яка ще не завершила виконання.

```text
  i1: add %rax, %rbx    # %rbx записується лише на стадії WB (такт 5)
  i2: sub %rbx, %rcx    # %rbx читається на стадії ID (такт 3) -> ДАНІ ЩЕ СТАРІ! (RAW Hazard)
```

* **Класифікація залежностей:**
  1. **RAW (Read After Write / True Data Dependency):** Читання після запису. Справжня залежність.
  2. **WAR (Write After Read / Anti-dependency):** Запис після читання (виникає в Out-of-Order).
  3. **WAW (Write After Write / Output dependency):** Запис після запису (виникає в Out-of-Order).

* **Способи вирішення RAW-конфліктів:**
  1. **Апаратне пересилання даних (Data Forwarding / Bypassing):**
     Результат операції вже готовий на виході ALU після стадії EX (такт 3). Замість очікування запису в регістр на стадії WB, спеціальні мультиплексори передають результат безпосередньо з регістрів `EX/MEM` або `MEM/WB` на вхід ALU наступної інструкції!
  2. **Load-Use Data Hazard (Неминуча затримка 1 такт):**
     Для інструкції `load` дані надходять з пам'яті лише наприкінці стадії MEM (такт 4). Навіть із forwarding неможливо передати дані назад у часі на стадію EX наступної команди. Виникає обов'язкова апаратна затримка в **1 такт (Stall / Bubble)**.

```text
  Load-Use Затримка:
  lw  $s0, 0($sp) : [IF] -> [ID] -> [EX] -> [MEM] ------------\ (Forwarding)
  add $t0, $s0, $s1:       [IF] -> [ID] -> [STALL] -> [EX] <--/ 
```

### 3.3. Конфлікти керування (Control / Branch Hazards)
Виникають при виконанні інструкцій умовного переходу (`jne`, `beq`). Процесор не знає, яку інструкцію вибирати наступною (за адресою `PC+4` чи за адресою мітки), доки умова переходу не обчислиться в ALU.

* **Передбачення переходів (Branch Prediction):**
  1. **Статичне передбачення:** Наприклад, вважати, що переходи назад (у циклах) завжди здійснюються (Taken), а переходи вперед (умовні `if`) — ні (Not Taken).
  2. **Динамічне передбачення з 2-бітним насиченим лічильником (2-bit Saturating Counter):**
     Вимагає двох послідовних помилок для зміни передбачення, що запобігає постійним збоям на останній ітерації циклів.
  3. **Branch Target Buffer (BTB):** Апаратний кеш, що зберігає передбачені адреси переходів для негайного завантаження наступної інструкції на стадії IF.

```text
             Динамічний 2-бітний автомат передбачення переходів:
             
                 Taken             Taken             Taken
                 +---+             +---+             +---+
                 |   v             |   v             |   v
               +-------+  NotTaken +-------+  Taken  +-------+  NotTaken +-------+
               |  11   | --------> |  10   | ------> |  01   | --------> |  00   |
               |Strongly           |Weakly           |Weakly             |Strongly
               | Taken | <-------- | Taken | <------ |Not Tak| <-------- |Not Tak|
               +-------+   Taken   +-------+ NotTak  +-------+   Taken   +-------+
                                                       ^   |
                                                       +---+
                                                      NotTaken
```

## 4. Сучасні концепції високопродуктивних процесорів

### 4.1. Суперскалярна архітектура (Superscalar Execution)
Процесор має кілька паралельних конвеєрів (Multiple Issue) і здатний вибирати, декодувати та виконувати **по кілька інструкцій за один такт** ($\text{IPC} > 1$, наприклад, 4-way або 8-way decode у сучасних ядрах Intel/AMD/Apple M-серії).

### 4.2. Позачергове виконання (Out-of-Order Execution - OoO / Tomasulo Algorithm)
1. **In-Order Fetch/Decode:** Інструкції зчитуються та декодуються послідовно.
2. **Перейменування регістрів (Register Renaming):** Архітектурні регістри (RAX, RBX) відображаються на великий фізичний пул регістрів (Physical Register File - PRF, >200 регістрів). Це повністю ліквідує псевдозалежності **WAR** та **WAW**.
3. **Out-of-Order Execution:** Інструкції чекають готовності своїх операндів у **станціях резервування (Reservation Stations)** і виконуються у відповідних функціональних блоках (ALU, FPU, Load/Store) щойно з'являться дані, незалежно від їхнього порядку в програмі.
4. **In-Order Retirement / Reorder Buffer (ROB):** Результати записуються у буфер перевпорядкування (ROB) і фіксуються в архітектурному стані суворо в оригінальному порядку програми. Це гарантує **точні винятки (Precise Exceptions)** та безпечне відновлення при помилковому передбаченні переходу (Speculative Execution).

---

## ⚠️ Підводні камені та типові помилки (Pitfalls)

1. **Нерозуміння впливу невдалих передбачень переходів (Branch Misprediction Penalty):**
   У сучасних глибоких конвеєрах (довжина 14–20 стадій) помилка передбачення переходу призводить до скидання (flush) усіх інструкцій у конвеєрі, що коштує 15–20 тактів втраченої продуктивності на кожен промах.
2. **Спекулятивне виконання та вразливості типу Spectre/Meltdown:**
   Процесор спекулятивно виконує інструкції за передбаченим переходом до перевірки прав доступу. Хоча результати скидаються в разі помилки, стан L1-кешу змінюється, що створює витік інформації через побічні канали (Side-channel attacks).
3. **Loop Unrolling (Розгортання циклів):** Компілятори розгортають цикли, щоб зменшити кількість інструкцій умовного переходу і дати можливість планувальнику OoO ефективніше завантажувати паралельні ALU.
