# 04. Ієрархія пам'яті та кешування (Memory Hierarchy & Caches)

## 🎯 Ключові концепції (Core Concepts)
1. **Ієрархія пам'яті (Memory Hierarchy):** Компроміс між швидкістю, ємністю та вартістю (Регістри $\to$ L1/L2/L3 Кеші $\to$ RAM $\to$ SSD/NVMe).
2. **Принцип локальності (Locality of Reference):** Часова (Temporal) та просторова (Spatial) локальність.
3. **Організація кеш-пам'яті:** Розбиття фізичної адреси на Tag (тег), Set Index (індекс набору) та Block Offset (зміщення в рядку).
4. **Типи кешів:** Прямого відображення (Direct-Mapped), множинно-асоціативний ($N$-Way Set-Associative) та повністю асоціативний (Fully Associative).
5. **Політики запису та витіснення:** Write-Through vs Write-Back (Dirty bit), Write-Allocate, алгоритми LRU / Pseudo-LRU.
6. **Класифікація промахів кешу (3C / 4C Misses):** Compulsory (обов'язкові), Capacity (місткості), Conflict (конфліктні), Coherence (когерентності).
7. **Когерентність кешів (Cache Coherence) та протокол MESI:** Узгодженість пам'яті в багатоядерних системах.
8. **Оптимізація коду під кеш (Cache-Friendly Code):** Row-major порядок обходу масивів.

## 1. Ієрархія пам'яті (The Memory Pyramid)

Час доступу до центрального процесора вимірюється частками наносекунд, тоді як звернення до оперативної пам'яті вимагає сотень тактів. Ієрархія пам'яті створює ілюзію величезного сховища зі швидкістю найшвидшого рівня.

```text
  Швидкість / Вартість ^               [ Регістри CPU ]   (~0.5 ns, ~1 KB)
                       |             [ Кеш L1 (I/D) ]     (~1 ns, 32-64 KB)
                       |           [ Кеш L2 (Per-core) ]  (~3-5 ns, 512KB-1MB)
                       |         [ Кеш L3 (Shared LLC) ]  (~10-20 ns, 16-64 MB)
                       |       [ Оперативна пам'ять RAM ] (~50-100 ns, 16-128 GB)
                       |     [ NVMe SSD / Flash пам'ять ] (~10-50 μs, 1-4 TB)
  Ємність пам'яті      v   [ Жорсткі диски HDD / Мережа ] (~5-10 ms, >10 TB)
```

### 1.1. Середній час доступу до пам'яті (AMAT - Average Memory Access Time)
$$\text{AMAT} = \text{Hit Time} + (\text{Miss Rate} \times \text{Miss Penalty})$$
* Для багаторівневого кешу:
  $$\text{AMAT} = \text{Hit Time}_{L1} + \text{Miss Rate}_{L1} \times \left( \text{Hit Time}_{L2} + \text{Miss Rate}_{L2} \times \text{Miss Penalty}_{\text{RAM}} \right)$$

## 2. Принцип локальності звернень (Locality of Reference)

Програми використовують лише невелику частину свого адресного простору в будь-який короткий проміжок часу:

1. **Часова локальність (Temporal Locality):** Якщо пам'ять за певною адресою була прочитана/записана, з високою ймовірністю до неї знову звернуться найближчим часом (наприклад, змінні-лічильники циклів `for (int i=0; ...)`).
2. **Просторова локальність (Spatial Locality):** Якщо відбулося звернення до адреси $A$, з високою ймовірністю незабаром відбудеться звернення до сусідніх адрес $A+1, A+2$ (наприклад, послідовний прохід по масиву або виконання послідовних команд коду).
   * *Апаратний наслідок:* Кеш завантажує дані з RAM не по одному байту, а цілими блоками — **рядками кешу (Cache Lines / Blocks)**, розмір яких у сучасних архітектурах становить **64 байти**.

## 3. Внутрішня організація та адресація кеш-пам'яті

Кеш-пам'ять складається з $S = 2^s$ наборів (Sets), кожен з яких містить $E$ рядків (Lines / Ways). Кожен рядок містить блок даних розміром $B = 2^b$ байтів (зазвичай 64 байти), поле тегу (Tag) та біти стану (`Valid`, `Dirty`).
Загальна ємність кешу: $C = S \times E \times B$.

* **Розбиття $m$-бітної фізичної адреси процесора:**

```text
  +-----------------------+--------------------+---------------------+
  |   Tag (Тег) (t бітів) | Set Index (s бітів)| Block Offset (b біт)|
  +-----------------------+--------------------+---------------------+
  m-1                                          b+s b                 0
```

1. **Block Offset ($b = \log_2 B$ бітів):** Вказує конкретний байт всередині 64-байтного рядка (молодші 6 бітів).
2. **Set Index ($s = \log_2 S$ бітів):** Визначає номер набору (Set), в який потрапляє адреса.
3. **Tag ($t = m - (s + b)$ бітів):** Унікальний ідентифікатор, який порівнюється з тегами рядків для підтвердження попадання (Cache Hit).

```text
       Схема пошуку в N-канальному множинно-асоціативному кеші:
       
       Адреса -> [ Tag | Set Index | Offset ]
                            |
                            v
                    +---------------+
           Set 0    |               |
                    +---------------+
           Set i -> | Line 0 (Tag 0)| -> [Компаратор Tag] == Tag? -\
                    | Line 1 (Tag 1)| -> [Компаратор Tag] == Tag? --+-> HIT! -> Отримати байт за Offset
                    | ...           |                               |
                    | Line E (Tag E)| -> [Компаратор Tag] == Tag? -/
                    +---------------+
```

### 3.1. Типи структури кешів за асоціативністю ($E$)

1. **Прямого відображення (Direct-Mapped Cache, $E = 1$):**
   Кожна адреса пам'яті може потрапити **лише в один конкретний рядок** кешу ($\text{Set} = (\text{Address} / B) \bmod S$).
   * *Плюси:* Максимально простий і швидкий пошук (один компаратор).
   * *Мінуси:* Висока частота конфліктних промахів при почерговому доступі до двох адрес з однаковим індексом набору.
2. **Множинно-асоціативний ($N$-Way Set-Associative Cache, наприклад $E = 8$ або $E = 16$):**
   Кожен набір містить $E$ паралельних рядків. Блок пам'яті може розміститися в будь-якому з $E$ рядків свого набору.
   * Стандарт для L1 (8-way) та L2/L3 (16-way) сучасних CPU.
3. **Повністю асоціативний (Fully Associative Cache, $S = 1$):**
   Єдиний набір містить усі рядки кешу. Будь-який блок пам'яті може бути розміщений у будь-якому місці.
   * Вимагає порівняння тегів з усіма рядками одночасно через спеціальну асоціативну пам'ять (CAM). Використовується для малих буферів (наприклад, TLB).

## 4. Політики заміщення та запису (Write & Replacement Policies)

### 4.1. Алгоритми витіснення рядків (Replacement Policies)
Коли вибраний набір заповнений, а стається промах, необхідно вибрати рядок для витіснення:
* **LRU (Least Recently Used):** Витісняє блок, до якого не зверталися найдовше (вимагає апаратних бітів історії).
* **Pseudo-LRU (Деревоподібний LRU):** Швидка апроксимація через бінарне дерево прапорців.
* **Random:** Випадковий вибір (дуже простий апаратно, працює непогано для великих L3-кешів).

### 4.2. Політики запису (Write Policies)

| Політика | При попаданні в кеш (Write Hit) | При промаху повз кеш (Write Miss) |
| :--- | :--- | :--- |
| **Write-Through + No-Write-Allocate** | Запис виконується одночасно і в кеш, і в оперативну пам'ять (RAM). Трафік шини високий. | Запис іде напряму в RAM без завантаження блоку в кеш. |
| **Write-Back + Write-Allocate** *(Сучасний стандарт)* | Запис виконується **тільки в кеш**. Рядок позначається бітом модифікації (`Dirty = 1`). Запис у RAM відкладається до моменту витіснення блоку. | Блок завантажується з RAM у кеш (Write-Allocate), і запис здійснюється вже в кеш. |

## 5. Класифікація промахів кешу: Модель 3C / 4C

1. **Compulsory / Cold Misses (Обов'язкові / Холодні):** Перше в історії звернення до блоку пам'яті. Неминучі. Зменшуються збільшенням розміру блоку $B$.
2. **Capacity Misses (Промахи місткості):** Робочий набір даних програми перевищує загальний розмір кешу. Зменшуються збільшенням обсягу кешу $C$.
3. **Conflict Misses (Конфліктні):** Кілька активно використовуваних блоків претендують на один і той самий набір (Set), хоча в інших наборах є вільне місце. Зменшуються збільшенням асоціативності $E$.
4. **Coherence Misses (Промахи когерентності):** У багатоядерних системах інше ядро процесора записало дані в спільну лінію пам'яті, інвалідувавши копію в нашому кеші.

---

## 6. Когерентність кеш-пам'яті: Протокол MESI

У багатоядерних CPU кожне ядро має власний локальний L1/L2 кеш. Щоб уникнути читання застарілих даних, використовується апаратний протокол **MESI** (Snooping / Відстеження шини), де кожен рядок перебуває в одному з 4 станів:

```text
       [M] Modified   --- (Модифікований, тільки в цьому кеші, Dirty, пам'ять застаріла)
       [E] Exclusive  --- (Чистий, тільки в цьому кеші, відповідає пам'яті)
       [S] Shared     --- (Чистий, може бути присутнім у кешах інших ядер)
       [I] Invalid    --- (Недійсний / застарілий, читати заборонено)
```

---

## 7. Написання коду, оптимізованого під кеш (Cache-Friendly Code)

У мовах C/C++ двовимірні масиви зберігаються в пам'яті **по рядках (Row-Major Order)**:

```c
// ❌ ПОГАНО (Column-Major): стрибки по пам'яті з кроком N -> ПОСТІЙНІ CACHE MISSES
for (int j = 0; j < N; j++) {
    for (int i = 0; i < N; i++) {
        sum += matrix[i][j];
    }
}

//  ІДЕАЛЬНО (Row-Major): послідовний доступ -> Spatial Locality, робота Hardware Prefetcher
for (int i = 0; i < N; i++) {
    for (int j = 0; j < N; j++) {
        sum += matrix[i][j];
    }
}
```

## ⚠️ Підводні камені та типові помилки (Pitfalls)

1. **Хибне розділення ресурсів (False Sharing):**
   Два потоки на різних ядрах модифікують **різні незалежні змінні**, які випадково опинилися в одному 64-байтному рядку кешу. Протокол MESI буде постійно перекидати рядок між ядрами в стані `Invalid`, викликаючи падіння продуктивності в десятки разів.
   * *Вирішення:* Вирівнювання критичних змінних потоків за розміром рядка кешу (`alignas(64)` в C++).
2. **Неврахування розміру блоку при виборі кроку (Stride Misses):**
   Якщо крок доступу до масиву дорівнює або кратний розміру набору кешу, ефективна ємність кешу деградує до Direct-Mapped кешу з катастрофічною кількістю конфліктних промахів.
