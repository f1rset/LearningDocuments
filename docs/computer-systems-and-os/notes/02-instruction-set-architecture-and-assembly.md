# 02. Архітектура набору команд та асемблер x86-64 (ISA & Assembly Programming)

## 🎯 Ключові концепції (Core Concepts)
1. **Архітектура набору команд (ISA):** Головний інтерфейс між апаратною частиною та програмним кодом.
2. **Парадигми CISC vs RISC:** Філософія складності інструкцій (x86-64 проти ARM та RISC-V).
3. **Регістри архітектури x86-64:** Регістри загального призначення (GPR), підрегістри (RAX $\to$ EAX $\to$ AX $\to$ AL), покажчик інструкцій (RIP) та регістр прапорців (RFLAGS).
4. **Режими адресації операндів (Addressing Modes):** Безпосередня, регістрова, базова та масштабовано-індексна (SIB-адресація).
5. **Стек викликів та стек-фрейми (Call Stack & Stack Frames):** Зростання стека вниз, збережені кадри функцій.
6. **Угода про виклики (Calling Convention):** Стандарт System V AMD64 ABI, збереження регістрів (Caller-Saved vs Callee-Saved), 16-байтне вирівнювання стека.

## 1. Архітектурні філософії: CISC vs. RISC

| Критерій | CISC (Complex Instruction Set Computer) | RISC (Reduced Instruction Set Computer) |
| :--- | :--- | :--- |
| **Представники** | Intel x86, AMD64 | ARM, RISC-V, MIPS |
| **Довжина інструкцій**| Змінна (від 1 до 15 байтів у x86) | Фіксована (32 біти / 4 байти) |
| **Робота з пам'яттю** | Більшість інструкцій можуть читати/писати в ОЗП (напр., `add (%rax), %rbx`) | Архітектура Load/Store: обчислення лише в регістрах, доступ до ОЗП тільки через `ldr`/`str` |
| **Кількість інструкцій**| Сотні/тисячі спеціалізованих складних команд | Малий оптимізований набір простих команд |
| **Апаратне декодування**| Складний мікропрограмний декодер (розбиває CISC-інструкції на внутрішні $\mu$-ops) | Простий швидкий апаратний декодер |
| **Оптимізація** | Апаратна складність заради високої щільності коду | Розрахунок на інтелектуальні компілятори |

---

## 2. Регістри архітектури x86-64

Архітектура x86-64 надає 16 64-бітних регістрів загального призначення. Для зворотної сумісності кожен регістр дозволяє адресувати свої молодші 32, 16 або 8 бітів:

```text
  64 біти (RAX) =========================================================>
                  32 біти (EAX) =========================================>
                                  16 бітів (AX) =========================>
                                                  8 біт (AH)   8 біт (AL)
  [ ............................. | ............. | [  8 біт ] | [ 8 біт ] ]
  63                            32 31           16 15        8 7         0
```

* **Таблиця 16 регістрів загального призначення x86-64:**

| 64-бітний | 32-бітний | 16-бітний | 8-бітний | Призначення за стандартом System V ABI |
| :--- | :--- | :--- | :--- | :--- |
| `%rax` | `%eax` | `%ax` | `%al` | Повернення результату функції / Акумулятор |
| `%rdi` | `%edi` | `%di` | `%dil` | 1-й аргумент функції |
| `%rsi` | `%esi` | `%si` | `%sil` | 2-й аргумент функції |
| `%rdx` | `%edx` | `%dx` | `%dl` | 3-й аргумент функції / 2-й результат |
| `%rcx` | `%ecx` | `%cx` | `%cl` | 4-й аргумент функції / Лічильник циклу |
| `%r8` | `%r8d` | `%r8w` | `%r8b` | 5-й аргумент функції |
| `%r9` | `%r9d` | `%r9w` | `%r9b` | 6-й аргумент функції |
| `%rsp` | `%esp` | `%sp` | `%spl` | **Stack Pointer:** Покажчик на вершину стека |
| `%rbp` | `%ebp` | `%bp` | `%bpl` | **Base / Frame Pointer:** Базовий покажчик кадру |
| `%rbx` | `%ebx` | `%bx` | `%bl` | Callee-saved регістр |
| `%r10` - `%r11` | `%r10d`.. | `%r10w`.. | `%r10b`.. | Тимчасові регістри (Caller-saved) |
| `%r12` - `%r15` | `%r12d`.. | `%r12w`.. | `%r12b`.. | Збережені регістри (Callee-saved) |

* **Регістр `%rip` (Instruction Pointer):** Зберігає адресу наступної команди. В x86-64 підтримує RIP-відносну адресацію (`mov (%rip), %rax`), що дозволяє генерувати позиційно-незалежний код (PIC/PIE).
* **Регістр прапорців `RFLAGS`:**
  * `ZF` (Zero Flag): результат операції дорівнює нулю.
  * `SF` (Sign Flag): старший біт результату 1 (від'ємне число).
  * `CF` (Carry Flag): виникло беззнакове перенесення зі старшого біту (Overflow для `unsigned`).
  * `OF` (Overflow Flag): знакове переповнення (результат вийшов за межі діапазону Two's complement).

## 3. Режими адресації пам'яті (Memory Addressing Modes)

Синтаксис AT&T (використовується в GNU Assembler, Linux `gcc`/`gdb`): джерело зліва, призначення справа: `op src, dst`.

* **Загальна масштабовано-індексна форма (SIB - Scale, Index, Base):**
  $$\text{Ефективна адреса} = \text{Imm} + \text{Reg}_{\text{base}} + (\text{Reg}_{\text{index}} \times \text{Scale})$$
  де $\text{Scale} \in \{1, 2, 4, 8\}$, а $\text{Imm}$ — стала зміщення (Displacement).

| Режим адресації | Синтаксис AT&T | Обчислення адреси / Операнд | Приклад коду |
| :--- | :--- | :--- | :--- |
| **Безпосередній (Immediate)** | `$val` | Числове значення $val$ | `mov $42, %rax` |
| **Регістровий (Register)** | `%reg` | Значення в регістрі $R[reg]$ | `mov %rbx, %rax` |
| **Прямий (Absolute)** | `Imm` | $M[\text{Imm}]$ | `mov 0x4000, %rax` |
| **Непрямий (Indirect)** | `(%rb)` | $M[R[rb]]$ | `mov (%rbx), %rax` |
| **Базовий зі зміщенням** | `Imm(%rb)` | $M[\text{Imm} + R[rb]]$ | `mov 8(%rbp), %rax` |
| **Індексований** | `Imm(%rb, %ri)` | $M[\text{Imm} + R[rb] + R[ri]]$ | `mov 4(%rbx, %rcx), %rax` |
| **Повний SIB-режим** | `Imm(%rb, %ri, s)` | $M[\text{Imm} + R[rb] + R[ri] \cdot s]$ | `mov 8(%rbx, %rcx, 4), %rax` |

* **Команда `lea` (Load Effective Address):**
  Обчислює адресу за формулою SIB, але **НЕ звертається до пам'яті**, а просто записує результат арифметики в цільовий регістр:
  ```assembly
  lea (%rdi, %rsi, 4), %rax   # rax = rdi + 4 * rsi (швидке множення на 5, 9 або обчислення індексу масиву)
  ```

## 4. Стек викликів та стек-фрейми (The Call Stack)

Стек росте **згори вниз (від старших адрес пам'яті до молодших)**. Регістр `%rsp` завжди вказує на поточну вершину стека (останній записаний 8-байтний елемент).

```text
  Старші адреси ^
                |  +-------------------------------------+
                |  | Аргументи виклику 7, 8, ...         |
                |  +-------------------------------------+
                |  | Адреса повернення (Return Address)  | <-- push-нута інструкцією `call`
                |  +-------------------------------------+
                |  | Збережений RBP попереднього кадру   | <-- %rbp вказує сюди
                |  +-------------------------------------+
                |  | Локальні змінні функції             |
                |  +-------------------------------------+
                |  | Тимчасові змінні / збережені рег.   |
  Молодші адреси|  +-------------------------------------+ <-- %rsp (Поточна вершина стека)
                v
```

* **Інструкції роботи зі стеком:**
  * `push %rax` $\iff$ `%rsp = %rsp - 8; mov %rax, (%rsp)`
  * `pop %rax` $\iff$ `mov (%rsp), %rax; %rsp = %rsp + 8`

## 5. Угода про виклики (System V AMD64 Calling Convention)

Стандартний протокол взаємодії функцій у Linux/UNIX (C/C++):

1. **Передача перших 6 аргументів через регістри:**
   `%rdi` (1-й), `%rsi` (2-й), `%rdx` (3-й), `%rcx` (4-й), `%r8` (5-й), `%r9` (6-й).
   Аргументи починаючи з 7-го передаються через стек (у зворотному порядку).
2. **Повернення результату:** Скалярні значення до 64 біт повертаються в `%rax`, 128 біт — у парі `%rdx:%rax`.
3. **Класифікація регістрів:**
   * **Caller-Saved (Volatile / Scratch):** `%rax, %rcx, %rdx, %rsi, %rdi, %r8-%r11`. Викликаюча функція повинна сама зберегти їх на стеку перед викликом `call`, якщо їхні значення потрібні пізніше.
   * **Callee-Saved (Non-volatile):** `%rbx, %rsp, %rbp, %r12-%r15`. Викликана функція зобов'язана зберегти їх перед модифікацією і відновити перед поверненням `ret`.
4. **Вирівнювання стека (Stack Alignment):**
   Безпосередньо перед виконанням інструкції `call` покажчик стека `%rsp` повинен бути **вирівняний по 16-байтній межі** (`%rsp % 16 == 0`). Оскільки сама команда `call` записує 8-байтну адресу повернення на стек, всередині прологу функції стек зміщений на 8 байтів (`%rsp % 16 == 8`).

```assembly
# Приклад канонічного прологу та епілогу функції:
.globl my_function
my_function:
    push %rbp              # Зберігаємо старий покажчик кадру (тепер %rsp вирівняний по 16 байт)
    mov %rsp, %rbp         # Встановлюємо новий frame pointer
    sub $16, %rsp          # Виділяємо 16 байтів на стеку під локальні змінні

    # ... тіло функції ...

    mov %rbp, %rsp         # Звільняємо локальні змінні
    pop %rbp               # Відновлюємо старий base pointer
    ret                    # Знімає адресу повернення зі стека і робить jmp туди
```

## ⚠️ Підводні камені та типові помилки (Pitfalls)

1. **Порушення 16-байтного вирівнювання стека перед викликом функцій C-бібліотеки:**
   Якщо перед інструкцією `call printf` стек не вирівняний по 16 байтах, виклик впаде із сигналом `SIGSEGV` (Crash) всередині SIMD/SSE інструкцій (наприклад, `movaps`), які апаратно вимагають 16-байтного вирівнювання.
2. **Плутанина між синтаксисами AT&T та Intel:**
   * AT&T (`gcc`, Linux): `mov $10, %rax` (джерело $\to$ призначення, префікси `%` та `$`).
   * Intel (Windows, MSVC, NASM): `mov rax, 10` (призначення $\leftarrow$ джерело, без префіксів).
3. **Обнулення 64-бітного регістра через 32-бітний запис:**
   В архітектурі x86-64 будь-яка операція запису в 32-бітний підрегістр (наприклад, `mov %ebx, %eax` або `xor %eax, %eax`) **автоматично обнуляє старші 32 біти** 64-бітного регістра `%rax` (Zero-extension)!
