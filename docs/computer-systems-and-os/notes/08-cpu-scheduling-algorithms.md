# 08. Алгоритми планування процесора (CPU Scheduling Algorithms)

## 🎯 Ключові концепції (Core Concepts)
1. **Цикл сплесків процесора та вводу-виводу (CPU-I/O Burst Cycle):** Процеси, орієнтовані на обчислення (CPU-bound) проти орієнтованих на ввід/вивід (I/O-bound).
2. **Типи планування:** Витискальне (Preemptive) та невитискальне (Non-preemptive).
3. **Метрики ефективності планувальника:** Throughput, Turnaround Time, Waiting Time, Response Time.
4. **Класичні алгоритми планування:** FCFS (ефект конвою), SJF та SRTF (оптимальність за часом очікування), Round Robin (RR, вибір кванта $q$), Пріоритетне планування та старіння (Aging).
5. **Багаторівневі черги зі зворотним зв'язком (MLFQ):** Адаптивне розділення CPU-bound та I/O-bound задач.
6. **Сучасні планувальники:** Повністю справедливий планувальник Linux (CFS - Completely Fair Scheduler), поняття `vruntime` та червоно-чорні дерева (Red-Black Tree).

---

## 1. Основи планування процесора (CPU Scheduling Basics)

Планувальник ядра ОС вирішує, якому з процесів у стані `Ready` надати фізичне ядро CPU:

```text
       CPU-I/O Сплески процесу:
       +------------------+------------------+------------------+
       | CPU Burst (Рахує)| I/O Wait (Диск)  | CPU Burst (Рахує)| ...
       +------------------+------------------+------------------+
```

* **CPU-Bound процеси:** Тривалі сплески обчислень, рідкісний I/O (наприклад, навчання нейромереж, рендеринг відео, наукові розрахунки).
* **I/O-Bound процеси:** Короткі спалахи CPU і тривале очікування вводу-виводу (наприклад, текстові редактори, веб-сервери, GUI).
* **Невитискальне планування (Non-preemptive / Cooperative):** Процес утримує CPU доти, доки сам добровільно не віддасть його (викликом `yield()`, очікуванням I/O або завершенням `exit()`).
* **Витискальне планування (Preemptive):** Ядро ОС може примусово забрати CPU у процесу за сигналом апаратного таймера або при появі більш пріоритетної задачі.

## 2. Критерії оптимізації планувальника (Scheduling Metrics)

1. **Завантаження CPU (CPU Utilization):** Відсоток часу, коли CPU виконує корисну роботу (мета: $40\%\dots 90\%$).
2. **Пропускна здатність (Throughput):** Кількість процесів, завершених за одиницю часу.
3. **Час обігу (Turnaround Time $T_{\text{turnaround}}$):** Повний час від моменту появи процесу в системі до його повного завершення:
   $$T_{\text{turnaround}} = T_{\text{completion}} - T_{\text{arrival}}$$
4. **Час очікування (Waiting Time $T_{\text{waiting}}$):** Сумарний час, проведений процесом у черзі `Ready` в очікуванні CPU:
   $$T_{\text{waiting}} = T_{\text{turnaround}} - T_{\text{burst}}$$
5. **Час відгуку (Response Time $T_{\text{response}}$):** Час від подання запиту до першої реакції системи (критично для інтерактивних GUI).

## 3. Класичні алгоритми планування (Scheduling Algorithms)

### 3.1. Перший прийшов — перший обслужений (FCFS / First-Come, First-Served)
Процеси виконуються суворо в порядку їхнього прибуття. Невитискальний.
* **⚠️ Ефект конвою (Convoy Effect):** Якщо перший процес виконує довгий CPU-сплеск (наприклад, 100 мс), усі короткі I/O-bound процеси (по 1 мс) змушені стояти в черзі, що призводить до жахливого середнього часу очікування та простою пристроїв I/O.

### 3.2. Найкоротша задача першою (SJF / Shortest Job First)
CPU виділяється процесу з найменшим часом наступного CPU-сплеску:
* **Теоретична оптимальність:** SJF доведено мінімізує середній час очікування серед усіх невитискальних алгоритмів.
* **Проблема реалізації:** Ядро не може заздалегідь знати точну тривалість наступного сплеску. Її прогнозують через експоненційне згладжування минулих сплесків:
  $$\tau_{n+1} = \alpha t_n + (1 - \alpha)\tau_n, \quad \alpha \in [0, 1]$$
* **SRTF (Shortest Remaining Time First):** Витискальна версія SJF. Якщо прибуває новий процес із меншим залишком часу, ніж у поточного, CPU негайно перемикається на новачка.

### 3.3. Карусельне планування (Round Robin - RR)
Кожен процес отримує фіксований неперервний проміжок часу на CPU — **квант часу (Time Quantum $q$)**, зазвичай від 10 до 100 мс. Якщо процес не завершився за час $q$, він витискається і стає в кінець черги `Ready`.

```text
       Черга Ready: [ P1 ] [ P2 ] [ P3 ]
       Діаграма Ганта (квант q = 4 мс):
       +-------+-------+-------+-------+
       |  P1   |  P2   |  P3   |  P1   | ...
       +-------+-------+-------+-------+
       0       4       8      12      16
```

* **Вибір кванта $q$:**
  * Якщо $q \to \infty \implies$ алгоритм вироджується у FCFS.
  * Якщо $q$ дуже малий (наприклад, $1\,\mu\text{s}$) $\implies$ гігантські накладні витрати на Context Switch.
  * **Правило:** $80\%$ CPU-сплесків повинні вкладатися в розмір одного кванта $q$.

### 3.4. Пріоритетне планування (Priority Scheduling) та голодування
Кожному процесу присвоюється числовий пріоритет. CPU виділяється процесу з найвищим пріоритетом.
* **⚠️ Голодування (Starvation / Indefinite Blocking):** Низькопріоритетний процес може ніколи не отримати CPU при безперервному надходженні високопріоритетних задач.
* **Вирішення — Старіння (Aging):** Поступове збільшення пріоритету процесу в міру того, як довго він чекає в черзі (наприклад, +1 пріоритет кожні 10 секунд очікування).

## 4. Багаторівневі черги зі зворотним зв'язком (MLFQ - Multi-Level Feedback Queue)

Ідеальний адаптивний алгоритм загального призначення:
1. Кілька черг із різними пріоритетами ($Q_0 > Q_1 > Q_2$).
2. Новий процес потрапляє у найвищу чергу $Q_0$ з найменшим квантом часу.
3. Якщо процес вичерпав увесь свій квант часу (CPU-bound) $\implies$ його пріоритет **знижується на 1 рівень** ($Q_0 \to Q_1$).
4. Якщо процес добровільно віддав CPU для I/O до вичерпання кванта $\implies$ він **залишається у високій черзі** (інтерактивні задачі мають максимальний пріоритет!).
5. **Priority Boost:** Періодично всі процеси скидаються назад у найвищу чергу $Q_0$ для уникнення голодування.

```text
       [Новий процес] ---> [ Черга Q0 (Пріоритет MAX, Квант 4 ms) ]
                                      | (Вичерпав квант)
                                      v
                           [ Черга Q1 (Пріоритет MID, Квант 8 ms) ]
                                      | (Вичерпав квант)
                                      v
                           [ Черга Q2 (Пріоритет MIN, FCFS)       ]
```

---

## 5. Планувальник CFS у Linux (Completely Fair Scheduler)

Стандартний планувальник для звичайних процесів у сучасному ядрі Linux:

1. **Віртуальний час виконання (`vruntime`):**
   Лічильник фізичного часу, який процес провів на CPU, зважений на його пріоритет (`nice` значення від -20 до +19). Процеси з високим пріоритетом накопичують `vruntime` значно повільніше.
2. **Червоно-чорне дерево (Red-Black Tree):**
   Усі готові процеси зберігаються в самобалансованому двійковому дереві пошуку, відсортованому за зростанням `vruntime`.
3. **Вибір задачі:** Планувальник завжди вибирає найлівіший вузол дерева (процес з **найменшим `vruntime`**, операція $O(1)$) і віддає йому CPU.

```text
                 [ Червоно-чорне дерево CFS ]
                             (vruntime = 15)
                             /             \
                   (vruntime = 10)     (vruntime = 22)
                     /
        [Найлівіший вузол: vruntime = 4]  <-- НАСТУПНИЙ НА CPU!
```

---

## ⚠️ Підводні камені та типові помилки (Pitfalls)

1. **Інверсія пріоритетів (Priority Inversion):**
   Високопріоритетний процес блокується на м'ютексі, захопленому низькопріоритетним процесом, а середньопріоритетний процес витісняє низькопріоритетний. В результаті високий процес не виконується (причина аварії марсохода Mars Pathfinder 1997 року).
   * *Вирішення:* Протокол успадкування пріоритету (**Priority Inheritance**).
2. **Шкала `nice` у Linux:**
   Значення `nice` впливає на пропорцію виділеного часу логарифмічно: зміна `nice` на $1$ змінює процесорний час приблизно на $10\%$ незалежно від базового рівня.
