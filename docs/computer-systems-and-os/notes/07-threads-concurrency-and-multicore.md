# 07. Потоки виконання, паралелізм та багатоядерність (Threads, Concurrency & Multicore)

## 🎯 Ключові концепції (Core Concepts)
1. **Поняття потоку (Thread / Lightweight Process - LWP):** Базова одиниця виділення процесорного часу.
2. **Анатомія процесу vs потоку:** Спільні ресурси (Адресний простір, купа, файли) проти приватних ресурсів (Стек, регістри, лічильник RIP, TLS).
3. **Конкурентність vs Паралелізм (Concurrency vs. Parallelism):** Логічне чергування задач проти фізичного одночасного виконання на багатьох ядрах.
4. **Рівні реалізації потоків:** User-Level Threads (N:1), Kernel-Level Threads (1:1), Гібридні моделі (M:N, горутини Go).
5. **POSIX Threads API (`pthreads`):** `pthread_create()`, `pthread_join()`, `pthread_detach()`.
6. **Багатоядерні архітектури:** Одночасна багатопотоковість (Hyper-Threading / SMT), симетрична багатопроцесорність (SMP), архітектури пам'яті UMA vs NUMA та прив'язка до ядер (Thread Affinity).

## 1. Процеси проти потоків (Processes vs. Threads)

**Потік (Thread)** — це незалежна послідовність інструкцій всередині процесу, що планується ядром ОС для виконання на CPU:

```text
       ПРОЦЕС (Важковаговий ізольований контейнер ресурсів)
  +-------------------------------------------------------------------+
  | Спільні для всіх потоків ресурси:                                 |
  |  [ Сегмент коду (Text) ]  [ Сегмент даних (Data/BSS) ]  [ Купа ]  |
  |  [ Таблиця відкритих дескрипторів файлів (FD Table) ]             |
  |  [ Обробники сигналів, поточний каталог, права UID/GID ]          |
  +-------------------------------------------------------------------+
  |                                                                   |
  |  +-------------------+   +-------------------+   +-------------+  |
  |  | Потік 1 (Thread 1)|   | Потік 2 (Thread 2)|   | Потік 3 ... |  |
  |  | - Регістри (RIP)  |   | - Регістри (RIP)  |   |             |  |
  |  | - Власний Стек    |   | - Власний Стек    |   |             |  |
  |  | - TLS пам'ять     |   | - TLS пам'ять     |   |             |  |
  |  +-------------------+   +-------------------+   +-------------+  |
  +-------------------------------------------------------------------+
```

| Властивість | Процес (Process) | Потік (Thread) |
| :--- | :--- | :--- |
| **Адресний простір** | Повністю ізольований власний простір | Спільний з усіма іншими потоками того ж процесу |
| **Створення** | Дороге (`fork()`, копіювання сторінок, PCB) | Швидке та легковагове (лише стек і структура потоку) |
| **Перемикання контексту**| Повільне (скидання TLB, заміна `CR3`, промахи кешу) | Швидке (зміна лише регістрів та покажчика стека `RSP`) |
| **Комунікація** | Міжпроцесна взаємодія (IPC: пайпи, сокети, shm) | Прямий доступ до спільної пам'яті (купа, глобальні змінні) |
| **Стійкість до збоїв** | Падіння одного процесу не впливає на інші | Збій одного потоку (Segfault) вбиває весь процес |

## 2. Конкурентність проти Паралелізму (Concurrency vs. Parallelism)

> **💡 Інтуїція (Роб Пайк):**
> * **Конкурентність (Concurrency)** — це про **структурування** програми: здатність програми одночасно керувати багатьма справами (навіть на одному ядрі шляхом швидкого чергування за квантами часу).
> * **Паралелізм (Parallelism)** — це про **виконання**: фізичне одночасне виконання кількох дій на різних апаратних ядрах CPU.

```text
  Конкурентність (1 ядро CPU):
  Ядро 0: [Потік 1][Потік 2][Потік 1][Потік 3][Потік 2] ---------> Час

  Паралелізм (Багатоядерний CPU):
  Ядро 0: [Потік 1 ===================================] ---------> Час
  Ядро 1: [Потік 2 ===================================] ---------> Час
```

* **Закон Амдала (Amdahl's Law):** Теоретичне максимальне прискорення програми на $N$ процесорах, якщо частка $P$ коду може бути розпаралелена:
  $$\text{Speedup}(N) = \frac{1}{(1 - P) + \frac{P}{N}} \xrightarrow{N \to \infty} \frac{1}{1 - P}$$
  *(Якщо $5\%$ коду є послідовним ($1-P = 0.05$), максимальне прискорення не перевищить $20\times$ навіть на нескінченній кількості ядер!)*.

## 3. Моделі багатопотоковості (Multithreading Models)

```text
    Many-to-One (N:1)           One-to-One (1:1)           Many-to-Many (M:N)
   [ULT] [ULT] [ULT]            [ULT]  [ULT]  [ULT]        [Goroutine] [Goroutine]
     \     |     /                |      |      |            \    \    /    /
        \  |  /                   v      v      v             v    v  v    v
         [KLT]                  [KLT]  [KLT]  [KLT]           [KLT]    [KLT]
```

1. **Модель багато-до-одного (Many-to-One / $N:1$ - User-Level Threads / Green Threads):**
   Усі потоки керуються бібліотекою користувача. Ядро бачить лише 1 процес.
   * *Плюси:* Ультрашвидке створення та перемикання (без виклику `syscall`).
   * *Мінуси:* Якщо один потік викликає блокуючий ввід/вивід (`read()`), **блокується весь процес**; неможливо використовувати багатоядерність.
2. **Модель один-до-одного (One-to-One / $1:1$ - Kernel-Level Threads):**
   Кожен потік користувача напряму відповідає потоку ядра ОС (у Linux реалізовано через системний виклик `clone()`).
   * Стандарт для Linux (`NPTL` / `pthreads`), Windows, macOS, Java, Rust, C++.
3. **Гібридна модель (Many-to-Many / $M:N$ - Go Runtime, Erlang BEAM):**
   $M$ легковагових потоків (горутин) динамічно розподіляються планувальником мови на $N$ системних потоків ядра за алгоритмом **Work-Stealing**.

## 4. Базове програмування з POSIX Threads (`pthreads`)

```c
#include <pthread.h>
#include <stdio.h>

void* worker_thread(void* arg) {
    int id = *(int*)arg;
    printf("Hello from Thread %d!\n", id);
    return NULL;
}

int main() {
    pthread_t thread;
    int thread_id = 1;

    // Створення потоку
    pthread_create(&thread, NULL, worker_thread, &thread_id);

    // Очікування завершення потоку (аналог waitpid)
    pthread_join(thread, NULL);

    return 0;
}
```

## 5. Архітектури багатоядерних систем (Multicore Hardware Architecture)

### 5.1. Одночасна багатопотоковість (SMT / Intel Hyper-Threading)
Одне фізичне ядро CPU має **дубльовані регістри та лічильник команд (два логічних ядра)**, але ділить спільні блоки ALU, FPU та L1/L2 кеші. Якщо один потік чекає відповіді від оперативної пам'яті (Memory Stall), конвеєр перемикається на виконання інструкцій другого потоку.

### 5.2. Моделі пам'яті: UMA vs. NUMA
* **UMA (Uniform Memory Access / SMP):** Усі ядра мають однаковий час доступу до спільної RAM через єдину системну шину.
* **NUMA (Non-Uniform Memory Access):** Багатопроцесорні сервери. Кожен CPU-сокет має власну "локальну" оперативну пам'ять (швидкий доступ) та звертається до пам'яті сусіднього сокета через міжпроцесорну шину типу Intel UPI / AMD Infinity Fabric (повільний доступ).

```text
   NUMA Вузол 0 (Socket 0)                NUMA Вузол 1 (Socket 1)
  +------------------------+             +------------------------+
  | [CPU Core 0] [Core 1]  |  Intel UPI  | [CPU Core 2] [Core 3]  |
  |      \      /          | <---------> |      \      /          |
  |   [Локальна RAM 0]     |             |   [Локальна RAM 1]     |
  +------------------------+             +------------------------+
```

* **Прив'язка потоків (Thread Affinity / CPU Pinning):**
  Системний виклик `pthread_setaffinity_np()` жорстко закріплює потік за конкретним ядром CPU. Це усуває міграцію потоку між ядрами та зберігає дані "гарячими" в локальному L1/L2 кеші.

## ⚠️ Підводні камені та типові помилки (Pitfalls)

1. **Несинхронізований спільний доступ до пам'яті (Data Race):**
   Одночасна модифікація спільної змінної двома потоками (`counter++`) призводить до непередбачуваних результатів через неатомарність операції (Fetch-Modify-Store).
2. **Переповнення стека потоку (Thread Stack Overflow):**
   За замовчуванням потік створюється з фіксованим стеком (зазвичай 2–8 МБ у Linux). Виділення великих масивів на стеку всередині потоку викликає негайний збій програми.
3. **Оверхед на надмірну кількість потоків (Thread Over-subscription):**
   Створення 1000 системних потоків на 4-ядерному комп'ютері призводить до того, що процесор витрачає $90\%$ часу на перемикання контексту, а не на корисну роботу (для таких задач слід використовувати Thread Pool або асинхронний I/O).
